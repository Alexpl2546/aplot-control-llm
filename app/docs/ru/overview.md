# Обзор

## Назначение

Aplot Control LLM — настольный управляющий интерфейс для локальных LLM-серверов. Приложение хранит настройки и профили, запускает поддерживаемые движки, показывает состояние процесса и API, открывает документацию API и помогает передать endpoint другой программе.

Текущий стек: React + TypeScript + Zustand во frontend, Tauri 2 и Rust в desktop backend, SQLite для постоянных настроек, профилей и результатов. Источник запуска — [App.tsx](../../src/App.tsx); основные действия и состояние находятся в [control.ts](../../src/store/control.ts).

## Движки и экраны

Существующий UI сохраняет страницы dashboard, configuration, models, profiles, performance, logs, settings и API. Поддерживаются только локальные движки `llama_cpp` и `strata`; их отдельные требования описаны в [адаптерах](modules/engine-adapters.md). Чат, агенты и внешние API-подключения имеют отдельный жизненный цикл.

Библиотека может разрешить, проверить и скачать GGUF из публичного Hugging Face Hub. Фоновая очередь независима от выбранной страницы, а совместимость модели с каждым движком проверяется отдельно. Для Strata по-прежнему нужны подготовленные конфигурация и сопутствующие файлы: [контракт загрузок](modules/model-downloads.md).

API-раздел сохраняет существующую справку OpenAPI. В эту редакцию добавлены сведения о конкретном подключении, ручное копирование полей и preview шаблонов harness. Подробнее: [модуль подключений](modules/connections.md).

## Текущий статус подключений

Текущий native backend регистрирует `list_runs` и `run_connection({ runId })`. Список возвращает `RunInfo` менеджера запусков; target содержит engine, URL, обнаруженный model ID, настроенный context, ключ, протокол и managed-флаг выбранного запуска. В старом backend без `list_runs` UI явно использует совместимый `legacy-current` snapshot одиночного runtime. Этот fallback не является реестром нескольких запусков.

Внешний запрос harness проверяет адрес из frontend. Ограничения browser CORS и различия localhost между Windows, WSL и контейнером остаются видимыми. Harness registry описывает официально документированные схемы, но не утверждает, что установленная версия harness прошла smoke-проверку.

## Будущие границы

Планируемые supervisor, история независимых запусков, persistent connection records, запись конфигурации harness и проверка именно из harness не считаются реализованными этим модулем. UI не пишет файлы Hermes, DeepSeek Harness, Pi или OpenClaw.
