# Модуль профилей

## Область ответственности и исходники

Профили v2 включают аддитивную миграцию, редактирование с проверкой ревизии, импорт/экспорт JSON, защиту секретов, нативное разрешение конфигурации запуска, независимое дублирование и зафиксированные снимки восстановления. [bridge.ts](../../../src/features/profiles/bridge.ts) сохраняет непрозрачный нативный снимок рядом с привычным LaunchConfig редактора. UI и код запуска используют bridge через сервисный слой приложения.

Нативный код: [profile_store.rs](../../../src-tauri/src/profile_store.rs), [profile_recovery.rs](../../../src-tauri/src/profile_recovery.rs), [migrations.rs](../../../src-tauri/src/migrations.rs), [domain/profile.rs](../../../src-tauri/src/domain/profile.rs), [domain/secrets.rs](../../../src-tauri/src/domain/secrets.rs). [profileAdapters.ts](../../../src/features/profiles/profileAdapters.ts) содержит исторические helpers настроек; CRUD/recovery wrappers находятся в bridge.ts. Команды зарегистрированы в [lib.rs](../../../src-tauri/src/lib.rs).

## Контракты JSON и IPC

Формат обмена и SQLite хранят envelope `{schemaVersion: 2, profile: {...}, ...unknownEnvelopeFields}`. CRUD IPC возвращает поля профиля на верхнем уровне, а дополнительные поля envelope — в `envelopeExtensions`. Bridge сохраняет их; экспорт восстанавливает envelope без вложенной метаобёртки.

| Поле | Контракт |
| --- | --- |
| `id`, `name`, `description` | Стабильная идентичность и отображаемые метаданные. |
| `engine` | Строковый ID; будущие движки сохраняются в БД/экспорте. |
| `revision` | Положительная ревизия для проверки конкурентных изменений. |
| `model` | ID артефакта, старые пути, ID модели движка, неизвестные поля. |
| `engineOptions` | `{engine, values}` и расширения; новые записи bridge содержат значения выбранного движка. |
| `legacyConfig` | Необязательная конфигурация запуска с полной картой engineOptions по движкам. |
| `secretReferences` | JSON pointer или мигрированный ключ с непрозрачными provider/ID. |
| `createdAt`, `updatedAt`, `lastUsedAt`, `lastKnownGood` | Временные отметки и метаданные контрольной точки. |
| Неизвестные поля profile/model/options/envelope | Сохраняются при чтении, редактировании, записи, импорте/экспорте. |

Bridge принимает старые плоские/вложенные снимки, сохраняя исходные значения и неизвестные поля для экспорта. В активном выборе запуска доступны только `llama_cpp` и `strata`; legacy ID остаётся неактивным, показывается с причиной и не преобразуется в другой движок. Значения по умолчанию заполняют отсутствующие поля редактора только для поддерживаемого профиля; некорректные данные v2 вызывают ошибку. Нативное чтение сверяет ID/ревизию envelope со строкой SQLite. Будущие версии, повреждённый JSON и конфликт ревизий не вызывают legacy CRUD fallback.

## Хранилище и миграция

При старте БД вызывается `migrations::migrate` после инициализации старых таблиц. Версия 1 создаёт журнал миграций и `launch_profiles_v2`, `profile_secrets`, `model_artifacts`, `artifact_files`, `artifact_consumers` в immediate-транзакции. Обязательные столбцы проверяются до фиксации успеха. Несовместимая существующая таблица, ошибка преобразования и будущая версия БД прерывают миграцию.

Копируются прежние ID, метаданные, полные конфигурации и неизвестные поля. Заполненные глобальные настройки движков прежней версии сохраняются как детерминированные профили `legacy-global-*`; стандартные/пустые настройки не создают профилей. Legacy-профиль можно посмотреть и экспортировать, но запуск требует нового профиля с `llama_cpp` или `strata`, выбранного пользователем. Старые строки, исходный kv.settings, legacy-ключи восстановления, события, избранное и история бенчмарков не меняются. Миграция не перемещает и не удаляет веса.

## CRUD, файлы и дублирование

Аргументы Tauri используют camelCase. Все команды ниже зарегистрированы.

| Команда | Поведение |
| --- | --- |
| `list_profiles_v2` | Очищенные профили, сортировка по использованию/обновлению. |
| `get_profile_v2({id})` | Очищенный профиль либо null; повреждённая строка вызывает ошибку. |
| `save_profile_v2({profile, expectedRevision})` | Null создаёт ревизию 1; совпадение обновляет/повышает ревизию; устаревшее изменение конфликтует. |
| `delete_profile_v2({id, expectedRevision})` | Требует совпадения ревизии; отсутствующая/устаревшая строка конфликтует. |
| `import_profile_v2({profileJson})` | Envelope v2/v1 или старый профиль; совпадение даёт новый ID/имя. Некорректная явно указанная или будущая версия отклоняется. |
| `export_profile_v2({id})` | Envelope v2 без значений секретов, со ссылками/неизвестными полями. |
| `import_profile_file_v2({path})` | Нативное чтение UTF-8 JSON до 8 МиБ с тем же обработчиком. |
| `export_profile_file_v2({id, path})` | Запись очищенного envelope в файл .json. |
| `duplicate_profile_v2({id, newId, name, expectedRevision})` | Копия с ревизией 1 и новыми ссылками секретов после проверки исходной ревизии. |

Дублирование копирует шифротекст без возврата открытого значения. Повторные ссылки согласованы; удаление исходника не ломает копию. Экспортируемые ссылки не содержат шифротекст для другой установки. Старый экспорт также удаляет значения секретов.

## Секреты и конфигурация запуска

Строковые ключи секретов (варианты apiKey/token/password/secret/authorization) обнаруживаются рекурсивно, включая расширения. Флаг `--api-key`, `--token=...` или `--password` защищает всю строку extraArgs с точным сохранением кавычек/пробелов. Новые секреты удаляются из JSON и сохраняются как Windows DPAPI ciphertext в транзакции профиля. Неиспользуемые текущие записи шифротекста удаляются; запись новых открытых секретов на других ОС завершается ошибкой.

Пустое очищенное поле сохраняет ссылку. Непустая обычная замена защищённой extraArgs удаляет ссылку этой строки. Универсального редактора раскрытия/копирования/удаления секретов нет. DPAPI требует исходный контекст пользователя/машины Windows. Мигрированные legacy-ссылки разрешаются из неизменённых исходных профилей/настроек.

`resolve_profile_launch_config({id})` / `resolveProfileLaunchConfig(id)` возвращает новую конфигурацию с полной картой движков. Выбранные нативные значения накладываются на legacy-снимок. Восстанавливаются только секреты запуска; секреты расширений profile/model/envelope исключены. Проверяются owner/profile/provider DPAPI-ссылок. Отсутствующие, повреждённые, некорректные или недоступные ссылки вызывают явную ошибку. Разрешение не записывает БД.

Результат содержит временные открытые значения: он передаётся непосредственно в запуск, без кеширования в редакторе/состоянии профиля, логирования, сохранения как профиль или экспорта. Значения по умолчанию, подготовка адаптера и неизменяемые снимки запусков находятся в сервисе запуска и адаптерах движков.

## Зафиксированные снимки восстановления

Новые ключи: `last_known_good_profile_v2` и `last_known_good_router_v2`. Снимки фиксируют полные envelope/config/settings и зашифрованный резерв vault независимо от текущих строк секретов. Изменение/удаление живого профиля не удаляет зафиксированные конфигурацию/шифротекст. Чтение возвращает очищенные профили/настройки без vault в UI.

| Команда | Поведение |
| --- | --- |
| `mark_profile_good_v2({id, expectedRevision})` | Проверяет ревизию, фиксирует профиль, обновляет отметки использования/успеха без изменения ревизии конфигурации. |
| `last_known_good_profile_v2` | Очищенная контрольная точка либо null. |
| `restore_last_known_good_profile_v2` | Транзакционно восстанавливает профиль/vault и возвращает новую очищенную ревизию. |
| `mark_router_good_v2({snapshot})` | Проверяет ревизии профилей llama.cpp; фиксирует профили БД и фактические config/settings роутера. |
| `last_known_good_router_v2` | Очищенная точка роутера либо null. |
| `restore_last_known_good_router_v2` | Транзакционно восстанавливает профили/vault и выбранные несекретные настройки роутера. |

Только отсутствие нового ключа разрешает чтение старого raw-ключа. Повреждённый новый снимок вызывает ошибку; legacy-чтение не переписывает исходные ключи. Явное восстановление может вернуть удалённый профиль или исправить повреждённый живой envelope. Новая ревизия выше текущей SQL-ревизии и ревизии снимка; контрольная точка сохраняет зафиксированную ревизию.

Восстановление роутера накладывает разрешённые несекретные поля на текущие settings, сохраняя язык/тему/dashboard/неизвестные поля. Ключ роутера становится ссылкой восстановленного профиля. После восстановления профиль разрешается заново, а `launch.engineOptions.llama_cpp.routerApiKey` передаётся во временные настройки запуска роутера. UI-снимки остаются очищенными; расшифрованный ключ не записывается в глобальные settings.

## Проверки и доказательства сохранности

[profileV2.test.ts](../../../tests/profileV2.test.ts) покрывает преобразования bridge, будущие поля/карты движков, ревизии, wrappers и recovery payload. Нативные тесты покрывают откат/повторяемость миграции, DPAPI, принадлежность ссылок, дублирование, восстановление после изменения/удаления, очистку экспорта, защиту extraArgs и конфигурацию запуска.

Полный нативный прогон профилей прошёл 122 теста библиотеки (6 пропущены), интеграционный Windows activation тоже прошёл. Целевые TypeScript-тесты профилей/моделей прошли 15 проверок; `npm run typecheck` прошёл. Числа относятся к общему checkout на момент проверки.

Отдельный игнорируемый тест использует `APLOT_MIGRATION_SOURCE` с путём baseline-копии и `APLOT_MIGRATION_REPORT` с путём JSON-отчёта. Из app: `cargo test --locked --manifest-path src-tauri/Cargo.toml migrations::tests::migration_copy_preserves_real_baseline -- --ignored --exact`. Источник открывается только для чтения, временная копия мигрирует дважды; сравниваются полные исходные схемы/ячейки/байты файла. Рабочая БД запрещена как источник.

Миграционная проверка сохранила 40 прежних профилей и создала 44 профиля v2 с четырьмя глобальными. Все пять исходных таблиц и обе raw-записи восстановления/settings остались неизменными; integrity ok, байты источника не изменились. FNV-дайджесты служат метками; assertions сравнивают полные данные.

## Текущие ограничения

model.artifactId пока не заменяет старые пути. Нет универсального интерфейса раскрытия/удаления секретов или переносимого экспорта шифротекста. Восстановление требует исправного шифротекста и исходного контекста DPAPI. Значения по умолчанию/совместимость определяют адаптеры. Эти ограничения не разрешают скрытый fallback или изменение исходных legacy-данных.

Во вкладке профилей показаны только сохранённые профили Aplot. Автообнаруженные конфигурации Strata относятся к библиотеке моделей и не добавляются к карточкам или счётчику профилей. Общие поля KV/GPU llama.cpp не показываются как параметры native Strata.
