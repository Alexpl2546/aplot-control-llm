# Задачи агентов на хосте

`src-tauri/src/tasks/` владеет сессиями задач агентов в процессе приложения, а не в окне. Перенесены Codex, Claude и Hermes. Задача Hermes с автозапуском локального сервера пока запускает его из окна перед отправкой сообщения; диктовка работает в сессии Hermes на хосте, а её кадры передаются окну напрямую, без записи в журнал.

## Данные

Хранилище задач, автомат подтверждений, декодер событий Codex и сохранение workspace выделены в общий `aplot-core` без Tauri. Инструменты `aplot_list_projects`, `aplot_list_agents` и `aplot_task_result` читают сохранённые данные на хосте и не требуют ответа окна. Проверяются активная сессия вызывающей задачи и принадлежность дочернего результата; ожидание результата ограничено 30 секундами. Делегирование и предложение нового сотрудника пока используют окно.

Миграция 3 добавляет `agent_tasks`, `agent_messages`, `agent_turns`, `agent_commands`, `agent_approvals`, `agent_task_imports` и журнал `task_events(seq, task_id, kind, revision, at, payload)`. Старая таблица `events` не связана. При первом запуске снимок рабочего пространства импортируется по runtime с сохранением ID; `agent_tasks_rollback` записывает историю хоста обратно в снимок.

## Команды

`agent_tasks_snapshot` возвращает задачи и cursor; `agent_tasks_subscribe` повторяет события после cursor через channel и дальше передаёт новые. `agent_task_send` принимает клиентский `commandId`; повтор возвращает первый результат. В сессии выполняется один ход, остальные ждут в `agent_turns`. Подтверждения переходят `pending` → `approved`/`denied`/`expired`/`stale` и привязаны к поколению worker.

## Управление Codex

[CodexTaskControls.tsx](../../../src/features/agent/CodexTaskControls.tsx) добавляет уточнение активного хода, проверку незакоммиченных изменений и создание дочерней задачи через fork. Host проверяет исходный аккаунт, проект, поколение процесса и идентификатор текущего хода. Уточнение отличается от обычного сообщения в очереди. Повтор команды с тем же `commandId` не создаёт повторную операцию; неопределённый результат fork не запускается автоматически заново.

## Git и сохранённые результаты

Панель Git показывает ветку, изменённые файлы и отдельные diff для индекса и рабочей копии. Чтение ограничено папкой проекта задачи; внешние diff-программы и textconv не запускаются. Панель не выполняет commit, reset, управление worktree или pull request.

Панель результатов сохраняет выбранный файл проекта как отдельную копию с версией, размером и SHA-256. Инструмент `aplot_save_artifact` доступен активной агентской сессии и принимает только относительный путь; задачу определяет host. Удаление результата удаляет управляемую копию, сохраняя исходный файл. Сохранённую копию можно открыть даже при недоступной папке проекта; изображения поддерживают явный предпросмотр.

События генерации изображения Codex отображаются как инструмент. Если Codex сообщает готовый файл изображения внутри проекта, host проверяет путь, размер и сигнатуру файла и сохраняет копию результата. Наличие функции в CLI не подтверждает доступность для конкретной модели, аккаунта и конфигурации подключения.

## Библиотека файлов проекта

Панель «Файлы проекта» использует ту же библиотеку, что и чат: сохранённые версии, поиск, выгрузку исходной копии и явное удаление. Файлы не копируются автоматически в рабочую папку задачи.

В новых сессиях внутренние инструменты `aplot_search_project_files` и `aplot_read_project_file` позволяют агенту находить файлы и читать ограниченный текст UTF-8/DOCX/XLSX. Проект определяется из задачи, связанной с приватным токеном, и проверяется активная сессия host. Модель не задаёт ID другого проекта или рабочий путь. Содержимое обозначается как справочные данные, а не инструкции или разрешения. PDF и изображения доступны в чате как вложения; эти инструменты не извлекают их текст.

## Создание документов агентом

Инструмент `aplot_create_document` создаёт DOCX/PDF по типизированным абзацам, заголовкам, спискам и таблицам или XLSX по листам и ячейкам. Результат сохраняется в библиотеке текущего проекта; рабочие файлы проекта не изменяются. Проект берётся из активной задачи, привязанной к приватному токену, а не из аргумента модели.

Ячейки XLSX могут содержать текст, конечное число, логическое значение, пустое значение или явно заданную формулу. Поддерживается ограниченный набор арифметики, ссылок на ячейки текущего листа и функций SUM, AVERAGE, MIN, MAX, COUNT, ROUND, IF. Внешние ссылки, DDE, сетевые и произвольные функции отклоняются. Aplot не вычисляет формулы и не подставляет выдуманный кэш; книга запрашивает пересчёт при открытии в табличном редакторе. Обычные строки, начинающиеся с `=`, остаются текстом.

## Внешние серверы MCP

В проекте Codex можно настроить сервер stdio с массивом аргументов или HTTP-сервер. Для удалённых адресов требуется HTTPS, для localhost разрешён HTTP. Секреты в аргументах и URL не принимаются. Ручной bearer-токен хранится Aplot с Windows DPAPI и передаётся в конфигурацию конкретной сессии Codex; собственное хранение конфигурации внешним runtime регулируется им отдельно.

Настройки применяются при создании, восстановлении и ветвлении сессии. Отключённые и удалённые серверы передаются как явные отключения с корректным транспортом. Изменения не останавливают уже работающий сервер в текущей сессии. Сохранение конфигурации не проверяет соединение; OAuth-вход и диагностика доступности сервера пока отсутствуют.
