# Загрузки моделей

## Назначение

Экран поддерживает два способа установки. Для Strata он показывает каталог установленного движка и запускает его штатную подготовку полного набора: веса, packs, tokenizer и MTP, когда они нужны выбранной модели. Для llama.cpp он ищет репозитории GGUF в публичном Hugging Face Hub и загружает выбранную квантовку целиком в папку библиотеки. Также можно открыть репозиторий по `owner/repo` или ссылке HF.

Загрузки работают отдельно от store запусков и benchmark jobs; переход между экранами не отменяет работу. Скачивание, проверка совместимости и готовность движка — отдельные состояния.

Слои находятся в [Rust-модуле](../../../src-tauri/src/downloads/mod.rs), [frontend service](../../../src/features/modelDownloads/service.ts) и [библиотеке моделей](models.md). История загрузок и установка сохраняются отдельно от пересоздаваемого каталога артефактов.

## IPC-команды

Все структуры используют camelCase. Команды зарегистрированы в Tauri; типы результатов определены в Rust-модуле загрузок и frontend service.

| Команда | Аргументы | Результат |
| --- | --- | --- |
| `strata_model_catalog` | `{ rootValue }` | Каталог моделей и вариантов из установленного Strata |
| `start_strata_model_preparation` | `{ recipeId, rootValue, destination, existingDirectories }` | `PreparationStatus`; штатная подготовка Strata продолжается асинхронно |
| `model_preparation_status` | нет | Текущая или последняя сохранённая `PreparationStatus` |
| `cancel_model_preparation` | нет | Запрос остановки подготовки Strata и принадлежащих ей дочерних процессов |
| `search_model_downloads` | `{ query, engine, limit?, cursor?, sort?, allGguf? }` | Страница `{ items, nextCursor }` с метаданными моделей; `apps=llama.cpp` и `filter=gguf`, при `allGguf=true` фильтр приложения снят. `sort`: downloads/lastModified/likes; limit по умолчанию 12, максимум 50 на страницу |
| `resolve_model_download` | `{ source }` | `ResolvedDownload`: репозиторий, immutable revision, издатель, ссылки и доступные файлы/варианты |
| `prepare_model_download` | `{ selection, destination }` | `DownloadPlan`: полный проверенный набор, уникальная папка, размер, свободное место и предупреждения |
| `start_model_download` | `{ planId }` | Сохранённая `DownloadTask`; передача продолжается асинхронно |
| `list_model_downloads`, `get_model_download` | `{}` / `{ id }` | Авторитетный снимок очереди или одной задачи |
| `pause_model_download`, `resume_model_download` | `{ id }` | Обновлённая задача; продолжение доступно после паузы или прерывания |
| `cancel_model_download` | `{ id }` | Остановленная задача с сохранёнными staging-файлами |
| `remove_model_download_partial` | `{ id }` | Удаление только временных файлов выбранной задачи |
| `model_download_destination` | `{ engine? }` | `<папка приложения>/models/llama` либо `models/strata`; по умолчанию llama.cpp |

`ResolvedDownload` содержит `source`, `repoId`, `revision`, `publisher`, `repositoryUrl`, `licenseUrl`, `files`, `variants` и необязательный `suggestedFile`. У файла есть относительный `path`, размер, необязательный LFS SHA-256, роль `model`/`shard`/`mmproj` и необязательный quantization. Вариант описывает полный список файлов и общее число байт. Выбор части split-модели разворачивается в полный набор; неполный набор не запускается. `mmproj` выбирается отдельно.

`DownloadPlan` фиксирует `planId`, источник, repo, revision, полный список файлов, `destination`, уникальный `finalPath`, `totalBytes`, `availableBytes` и `warnings`. `DownloadTask` содержит идентификатор и sequence, план, загруженные и общие байты, скорость, текущий файл, даты, необязательные ошибку/путь установки и описание проверки.

Поиск возвращает `{ items, nextCursor }`; курсор следующей страницы применяется к тому же запросу и сортировке. Элемент содержит необязательные `parameterCount`, `contextLength`, `sizeBytes`, `architecture`, `baseModel`, `license`, `description` из метаданных HF, а также `repoId`, `publisher`, `repositoryUrl`, число скачиваний и отметок, `tags`, необязательные `pipelineTag`/`lastModified` и признак `gated`. Поиск не скачивает файлы; разрешение репозитория отдельно проверяет доступ и предлагает фактически существующие GGUF. Метка приложения в HF помогает найти подходящий формат, но не подтверждает поддержку архитектуры конкретной сборкой llama.cpp.

Размер GGUF в карточке — ориентир из метаданных HF, а не сумма всех квантований репозитория. Точный размер полного набора виден после выбора GGUF. Неизвестные значения не подменяются оценкой. Три готовых рецепта llama.cpp находятся в сворачиваемом разделе быстрого старта; они не ограничивают поиск.

Папка по умолчанию определяется отдельно для каждого движка; ручной выбор сохраняется при переключении вкладок в текущем окне. Существующие модели автоматически не переносятся. Путь назначения должен быть абсолютным и доступным для записи. Загрузка запрещена внутрь каталогов `downloads`, `cache`, `modules`, `engines` и `data` корня установки и внутрь хранилища компонентов; symlink/junction в любом родительском пути запрещён. Для Strata выбранный путь передаётся как `--data-dir`, чтобы разместить там также подготовленные данные, а не только GGUF. Конфигурации запуска остаются в папке установленного Strata.

## Каталог и подготовка Strata

Источник каталога — `tools/strata_mcp.py` установленного Strata, его `Strata.model_table()` и таблицы `setup.py`. Это тот же источник семейств и размеров, который использует оригинальная новая оболочка. Каталог включает обычные и отдельные семейства `OWN_PATH_FAMILIES`, а не только прежние три рецепта Aplot. В установленном Strata v0.2.3.1 с движком 0.1.48 это Qwen3.8 Flash Next, Coder, Swift 1.5, Unsloth, Gyro, NVFP4 и Qwen3.6-35B-A3B с доступными им вариантами.

Отображаемые размер скачивания, потребность в памяти, experimental/images и оценка `on_this_pc` происходят из каталога движка. Оценка памяти — рекомендация: модель остаётся доступной для выбора. Реальную возможность подготовки, свободное место, поддержку GPU и необходимые файлы проверяет Strata. Если каталог установленного движка прочитать не удалось, приложение показывает ошибку; список для браузерного предпросмотра не выдаётся за результат чтения установки.

Подготовка запускает Python из собственного `.venv` Strata и `setup.py --setup --yes --no-start`. Она не запускает модель. Aplot передаёт выбранное семейство/размер отдельными аргументами, использует собственный `STRATA_SETTINGS_FILE` и не записывает настройки самостоятельной оболочки Strata. Готовые локальные файлы могут использоваться повторно; состав packs и других вспомогательных файлов определяет установщик движка.

Если собственная `.venv` Strata не содержит pip, обёртка вызывает встроенный `python -m ensurepip --upgrade` перед реальным `--setup`. При наличии pip, при `--help`/`-h` и при чтении каталога bootstrap не выполняется.

В части размещения данных обёртка Aplot заменяет автоматический перенос в `data_folder()`: выбранная папка принимает новые файлы, старые каталоги используются на месте. Скачивание, закреплённые ревизии, хэши и подготовку выполняет исходный setup движка.

`PreparationStatus` содержит `id`, `recipeId`, `state`, последние строки вывода, снимок `recipe`, `destination`, `rootPath`, необязательные `configPath` и `error`. Подготовка Strata — отдельная операция, не GGUF-задача `DownloadTask`: у неё нет общего с GGUF-очередью побайтового прогресса, паузы и удаления staging. Строки с `\r` показывают текущий этап и его процент, а не процент всей установки. После отмены или ошибки повтор использует сохранённые рецепт, папку и корень движка; уже завершённые шаги повторно использует штатный setup. Сохраняется последняя операция, а при восстановлении прежнее `installing` становится `interrupted`.

Завершение setup считается успешным только после проверки `strata-*.json`, engine executable, tokenizer и путей вспомогательных файлов. Затем каталог готовых моделей обновляется и сценарий установки рецепта сохраняет профиль. Если сохранение профиля завершилось ошибкой, его можно повторить отдельно без новой загрузки весов. Прямая загрузка произвольного GGUF оставляет создание профиля отдельным действием пользователя.

## Состояния и события

Состояния: `queued`, `resolving`, `downloading`, `verifying`, `installing`, `completed`, `pausing`, `paused`, `retry_wait`, `failed`, `cancelled`, `interrupted`.

Событие `download://updated` передаёт полный `DownloadTask`. `sequence` монотонно растёт для каждой задачи; UI сначала подписывается, затем получает snapshot и игнорирует события с уже обработанным sequence. Snapshot и SQLite остаются источником истины. Управление очередью не использует `control.ts` busy или `JobManager`.

Пауза считается завершённой после остановки записи и сохранения контрольной точки. При штатном выходе передача сохраняется как приостановленная; после аварийного завершения задача становится `interrupted` и не возобновляется без действия пользователя. Повтор сетевой ошибки использует ограниченный backoff; недостаток места, доступ и ошибка целостности требуют отдельного решения.

## Проверка и публикация

Hub branch/tag разрешается в immutable commit SHA до передачи. Каждый файл загружается потоково в `.part` внутри `<destination>/.aplot-staging/<downloadId>`. Staging не индексируется как модель и не сканируется как запускаемый файл. Проверяются размер и LFS SHA-256, если Hub предоставляет digest именно этого алгоритма; Xet ID или произвольный ETag не считается SHA-256. `verification: "source_sha256"` означает, что у каждого выбранного файла был исходный LFS SHA-256 и он совпал. `verification: "size_gguf_local_sha256_only"` означает, что размер и структура GGUF прошли проверку, но исходный digest отсутствовал хотя бы у одного файла. В этом случае `localSha256` — локально вычисленный digest для проверки локального состояния и восстановления; он не доказывает совпадение байтов с источником. Задача явно сообщает уровень проверки.

При возобновлении размер частичного файла сверяется с сохранённой контрольной точкой; Range применяется только при подтверждённом validator. Изменившаяся версия не дописывается к старым байтам. Перед публикацией проверяются GGUF и комплектность split-набора. Полный каталог атомарно переименовывается на том же томе в уникальный `finalPath`, затем его путь и manifest регистрируются в `model_installations`.

Частичная задача GGUF удаляет только свой staging-каталог и не перезаписывает существующую модель. Прямая загрузка GGUF не запускает код репозитория и не создаёт профиль автоматически. Установка готового рецепта дополнительно проверяет результат и сохраняет профиль. Файлы остаются обычной моделью пользователя; библиотека не копирует их для второго движка.

## Совместимость с движками

llama.cpp и Strata могут ссылаться на одну физическую копию GGUF, если файл совместим с установленной сборкой. Статус загрузки не является гарантией поддержки или успешного запуска.

Для Strata отдельно проверяются подготовленная конфигурация `strata-*.json`, tokenizer и сопутствующие файлы. Конфигурация должна находиться непосредственно в выбранном root Strata; папка данных модели может находиться на другом диске. Профиль хранит root и путь конфигурации, а не заменяет root папкой весов. Глобальная библиотека обнаруживает готовые конфигурации из root Strata, указанного в настройках.

Скачанный `qwen4exp` GGUF без проверенной конфигурации получает состояние `needsStrataPreparation`: карточка показывает «Нужна подготовка Strata» и остаётся видимой в фильтре Strata. Действие «Подготовить для Strata» открывает каталог подготовки; готовый источник движка модели ещё не присваивается. После обнаружения проверенной конфигурации состояние подготовки сменяется обычным действием настройки модели.

Загрузчик GGUF не создаёт конфигурацию Strata и не отмечает движок готовым без этой проверки. Для полноценной установки Strata используется его каталог и подготовка. Вход по токену HF, скачивание gated/private repositories, произвольные HTTPS-источники и произвольные safetensors snapshots не поддерживаются. Репозиторий с ограниченным доступом может появиться в поиске, но это не предоставляет право на скачивание.
