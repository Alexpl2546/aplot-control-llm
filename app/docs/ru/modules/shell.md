# Оболочка «Контур»

## Ответственность и границы

Редизайн внедрён в основной `app/` 13 октября 2026 года. Источник рабочей реализации — `app/src`; `_redesign/` остаётся архивом первого этапа. Production-код не импортирует файлы из архивной копии.

[App.tsx](../../../src/App.tsx) собирает оболочку, маршруты и существующие подписки. [KSidebar](../../../src/components/shell/KSidebar.tsx), [KTopbar](../../../src/components/shell/KTopbar.tsx) и [KStatusBar](../../../src/components/shell/KStatusBar.tsx) отображают состояние через control-фасад. Компоненты не владеют процессами, профилями, SQLite, заданиями или распределением ресурсов. Вызовы lifecycle продолжают идти через действия запусков и существующий IPC.

[useSidebarState](../../../src/components/shell/useSidebarState.ts) владеет только состоянием представления: закреплением, наведением, фокусом и компактным режимом. Настройки движков в него не входят. В окне до 1279 CSS px меню становится узкой полосой и раскрывается при наведении или фокусе; рабочая область всегда остаётся во второй колонке сетки.

## Запуск и подтверждение изменений

Карточка сервера и палитра Ctrl K используют один [useLaunchAction](../../../src/features/launches/useLaunchAction.ts). Чистый сценарий [launchActions](../../../src/features/launches/launchActions.ts) принимает типизированный снимок и порт действий; не импортирует React, Zustand или Tauri.

При несохранённых изменениях создание намерения не сохраняет профиль и не меняет запуск. Подтверждение выполняется через существующие `startManagedRun` / `restartManagedRun`, которые владеют сохранением и lifecycle. Перед исполнением повторно проверяются ID выбранного запуска, generation, черновик, настройки и занятость. Если цель или черновик изменились, действие отклоняется с пояснением. Отмена сохраняет черновик. Нативный HTML dialog удерживает фокус и поддерживает Escape.

Выбор серверов остаётся по устойчивому `runId`. [presentation](../../../src/features/launches/presentation.ts) содержит чистые правила состояний и цвет по ID, поэтому перестановка списка не меняет цвет сервера. Метки CH показывают текущую позицию и не являются идентификаторами lifecycle.

## Память и наблюдаемость

[memoryUsage](../../../src/features/resources/memoryUsage.ts) — чистая модель представления ресурсов, отдельная от [planner](../../../src/features/resources/planner.ts). Она использует существующий оценщик llama.cpp и типизированные входные снимки, не читает store и не вызывает IPC. Она не принимает решения о запуске и не резервирует память.

Итог RAM/VRAM берётся из системного runtime snapshot. Доли серверов являются оценками, а не измерениями PID. Поддерживаются только одиночные llama.cpp запуски с метаданными GGUF; другие движки и router остаются в неатрибутированном остатке. Если сумма оценок превышает измеренный расход, полоса и легенда используют одинаковые пропорциональные доли. Предупреждение называет VRAM и/или RAM; подсказка сохраняет исходную оценку. Расхождение не приписывается `--fit` без доказательства.

## Стили и сохранение возможностей

[styles/kontur/index.css](../../../src/styles/kontur/index.css) задаёт CSS-слои и семантические токены RU/EN, тёмной и светлой темы. Графики получают разрешённые цвета через [useCssVars](../../../src/lib/useCssVars.ts). Конфликтующие старые `!important` для padding карточки сервера сняты, так как важные правила имеют обратный приоритет слоёв.

Оболочка сохраняет библиотеку, профили двух движков, редакторы запуска, resource-plan preview, бенчмарки, логи, API и harness-подключения, setup, recovery, tray и настройку dashboard. Настраиваемый холст и сохранённые координаты виджетов не мигрируют. Выбор модели/движка/профиля доступен в раскрывающемся блоке карточки; скорость и TTFT остаются видны в сводке.

## Проверка модулей

`npm run verify:modules` и CI проверяют транзитивные runtime imports семи чистых входных модулей: launches/actions, launches/presentation, resources/memoryUsage, resources/planner, models/artifactCatalog, profiles/profileAdapters и connections/harnesses. Импорты интерфейса, store, services, React, Zustand и native API запрещены в их runtime-графе. Type-only зависимости допускаются. Отдельно проверяются импорты оболочки и отсутствие зависимости production-кода от архивного редизайна.

Это защита существующих границ, а не объявление всего плана реструктуризации завершённым. Control-store остаётся фасадом совместимости; legacy Rust-файлы и существующая SQL-зависимость `domain/secrets.rs` сохраняются. Полное разделение application/infrastructure относится к дальнейшей работе.
