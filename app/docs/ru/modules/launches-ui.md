# UI запуска и нескольких процессов

## Область

В заголовке запуска выбирается управляемый процесс; там же показываются его состояние и endpoint, доступны start/stop/restart для конкретного процесса. Опрос runtime и подписки на `run://log` / `run://state` собраны в [monitor.ts](../../../src/features/launches/monitor.ts). Store хранит runtime-метрики, логи, историю и черновики отдельно по `runId`; события со старым generation игнорируются.

Мост управляемых запусков находится в [tauri.ts](../../../src/services/tauri.ts), состояние и переходы профилей — в [control.ts](../../../src/store/control.ts), настройки движков — в [ServerHeader.tsx](../../../src/components/runtime/ServerHeader.tsx). Типы `RunInfo` и событий находятся в [runtime.ts](../../../src/types/runtime.ts).

## Идентификатор запуска и снимки профиля

Для сохранённого профиля используется устойчивый ID `profile:<profileId>`. У каждого запуска свой черновик настроек и конфигурации. Переключение селектора восстанавливает нужный черновик и runtime; изменение другого запуска не подменяет его процесс или телеметрию. Stop All вызывает менеджер запусков одной командой и обновляет состояние каждого процесса.

Сохранение и восстановление параметров профиля описано в [profiles.ts](../../../src/features/launches/profiles.ts). Текущие настройки движка сохраняются в `LaunchConfig.engineOptions`, неизвестные ключи остаются на месте, а восстановление известных параметров не меняет глобальные настройки интерфейса. Сохранённый профиль стартует под своим profile run ID. Если снимок запуска изменился, store останавливает и запускает этот же процесс с новым запросом; обычный restart использует сохранённый в менеджере снимок.

В UI-конфигурации хранится полная карта настроек по движкам. Native v2 bridge преобразует выбранную запись в `engineOptions: { engine, values }`, а остальные снимки движков и неизвестные поля оставляет в `legacyConfig.engineOptions`. Secret references перемещаются вместе с соответствующими значениями и остаются непрозрачными для редактора; разрешённые credentials используются только при запуске.

CRUD профилей использует v2 bridge: импорт/экспорт JSON-файлов, ожидаемые ревизии при сохранении/удалении и исходные v2-снимки. Повреждённые v2-записи показывают ошибку без перехода к legacy. Профили неизвестных движков остаются видимыми и доступными для экспорта, но выбор и запуск недоступны.

Раскрываемый каталог комплектов моделей внизу библиотеки получает native-метаданные через `model_catalog`. Он показывает каталоги сканирования, время, состояние файлов/шардов, размеры, зависимости, потребителей и отсутствующие файлы. Обновление повторяет сканирование метаданных; действий удаления нет. Браузерный пример явно сообщает, что сканирование файлов требует настольного приложения.

UI использует команды `start_run`, `list_runs`, `stop_run`, `restart_run`, `run_runtime`, `run_connection` и `stop_all_runs`. Старые глобальные серверные сессии продолжают идти через legacy facade, пока пользователь не запустит их через UI управляемых процессов.

## Бенчмарки и отмена

Для управляемого процесса обычный benchmark и trial автоподбора используют `start_benchmark_job`. Сервис подписывается на `job://state` и `job://progress`, опрашивает `list_jobs`, загружает готовый результат через `list_benchmarks` по `benchmarkId` и снимает подписки при завершении Promise. Кнопки отмены benchmark и автоподбора вызывают `cancel_job`; временный trial-процесс останавливается при очистке. Ограничения описаны в [документе о benchmark](../benchmarks.md).

Native benchmark-снимки разделяют фактический `run` и очищенный `editorConfiguration` с меткой `editorConfigurationSource: "caller"`. Общий [разбор конфигурации](../../../src/lib/benchmarkLaunchConfig.ts) принимает старые плоские снимки редактора и новый wrapper, отклоняя отдельный запрос запуска, повреждённые данные и несовпадение engine/context. Ранжирование, применение рекомендации и сохранение профилей используют извлечённые данные редактора; redaction-маркеры не становятся сохранёнными credentials. Применение сохраняет текущие ключи, а автосохранение сначала клонирует исходный профиль с native v2 перепривязкой ссылок.

V2-снимки успешного запуска сохраняют очищенные профили и непрозрачные ссылки. Готовность управляемого процесса фиксирует исходную revision один раз на generation; trial-процессы исключены. Rollback восстанавливает целевой профиль с новой revision, убирает его устаревший черновик и запускает с временным разрешением credentials. Другие процессы и их черновики сохраняются. ConfigurationView готовит запрос плана ресурсов в памяти; кнопка оценки запрашивает native-метрики без запуска процесса и записи router preset.

## Окна Web UI

Для готового llama.cpp запуска кнопка **Открыть Web UI** открывает встроенный интерфейс в отдельном окне приложения. Выбранный native-запуск предоставляет фактически назначенный порт и ключ, использованный при старте: редактирование другого профиля не меняет подключение. Ключ автоматически записывается в localStorage WebView для данного origin: `LlamaUi.config` и прежний `LlamaCppWebui.config`. Остальные настройки сохраняются; пустой ключ очищает старые credentials при повторном использовании порта. Это обычное хранилище credentials Web UI, отдельное от хранилища секретов профиля и Chrome. При ручном открытии адреса в Chrome ключ требуется ввести там отдельно.

Запуски single и router учитывают `webUi` профиля: современные флаги `--ui` / `--no-ui` и прежние `--webui` / `--no-webui`. Ранее запущенный роутер с отключённым UI нужно перезапустить в этой сборке. Сборка движка без встроенного HTML сообщает об ошибке. Bootstrap работает только для точного origin и главного frame; навигация остаётся в пределах сервера. Повторное нажатие активирует существующее окно запуска. Закрытие окна оставляет модель работающей; stop/restart закрывает окно этого запуска. Другие процессы и окна независимы. Главное окно сохраняет обычную логику закрытия в трей/выхода.

Авторизация и сохранение настроек проверяются в [webUiBootstrap.test.ts](../../../tests/webUiBootstrap.test.ts), флаги роутера — в [router.test.ts](../../../tests/router.test.ts), native URL/окна — в [web_ui.rs](../../../src-tauri/src/web_ui.rs).

Для Strata кнопка **«Открыть Web UI»** также доступна, когда выбранный запуск готов или занят генерацией. Открывается существующий интерфейс самой Strata (`serve/web`): чат, мониторинг и настройки. Дополнительный чат или сервер не устанавливается. Используются тот же идентификатор запуска, фактический порт, повторное открытие того же окна и правила закрытия/остановки. [Механизм авторизации Strata](../../../src-tauri/src/strata_web_ui_bootstrap.js) записывает JSON-строку в `strata.apikey` и обычную строку ключа в `sessionStorage["strata.monitor.key"]` для дополнительного API-монитора до исполнения скриптов страницы. История чатов, тема, параметры генерации и записи llama.cpp сохраняются. Пустой ключ старта очищает устаревшую авторизацию на повторно занятом порту. Ключ не попадает в URL. Во время загрузки сервера кнопка видна, но недоступна; настройка `webUi` llama.cpp на Strata не влияет. Установка без встроенного HTML возвращает ошибку.

## Проверка

Изоляция выбранных запусков и generation проверяется в [runsStore.test.ts](../../../tests/runsStore.test.ts). Захват и восстановление engine-настроек — в [profileV2.test.ts](../../../tests/profileV2.test.ts). Typecheck запускается командой `npm run typecheck` из `app/`.
