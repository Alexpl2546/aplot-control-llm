# Визуальная система Aplot Control LLM

Этот документ фиксирует актуальный визуальный язык desktop-приложения: реальные цвета и CSS-токены, их эффективные значения, формы контролов, состояния, движение, адаптивные правила и точки расширения. Это справочник для изменений интерфейса и передачи работы другому агенту.

## Источник истины и порядок каскада

Текущий style entry — [styles/kontur/index.css](../../src/styles/kontur/index.css), подключённый в [main.tsx](../../src/main.tsx). Сначала он помещает старые index.css, polish.css и studio.css в низкоприоритетный слой legacy. Затем идут дизайн-токены, базовые правила, компоненты, shell, экраны, responsive, стеклянный слой и движение:

    legacy → tokens → base → components → shell → screens → responsive → glass → motion

Токены базовой системы определены в [tokens.css](../../src/styles/kontur/tokens.css). Слой [glass.css](../../src/styles/kontur/glass.css) переопределяет часть значений для «Контур · Стекло», поэтому ниже отдельно приведены исходные семантические значения и эффективные стеклянные значения. Компоненты должны читать семантические роли --k-*, а не закреплять HEX-цвета напрямую.

При совпадении правил более поздний слой каскада имеет приоритет. features.css и agent-workspace-v3.css также находятся в слое glass и могут уточнять компоненты. Локальный компонентный стиль может задавать исключение, когда этого требует его функция.

## 1. Характер дизайна

Интерфейс — техническая рабочая среда и приборная панель под дымчатым стеклом. Основу составляют графит, прохладный светлый текст, тонкие контуры и один мягкий лаймовый акцент. Панели разделены прозрачностью, внутренним бликом и тенями; цветовые свечения показывают состояние системы и активный запуск.

Светлая тема использует те же роли и структуру: тёплый серо-зелёный фон, полупрозрачные белые поверхности, тёмный зелёно-графитовый текст и более глубокий зелёный акцент.

Правила характера:

- визуальная иерархия строится на контрасте, плотности и небольшом числе акцентов;
- лайм выделяет активность, фокус и главное действие;
- цвет конкретного запуска служит его идентификатором в списках и метриках;
- поверхности не получают тяжёлых рамок и сильных теней одновременно;
- размытие используется выборочно на крупных панелях и оверлеях, но не на каждой карточке;
- состояния различаются цветом вместе с текстом, индикатором или формой, а не одним цветом;
- цифры и технические идентификаторы отображаются компактно и точно.

## 4. Правила компонентов

### 4.1. Каркас приложения

- Desktop shell — две колонки: боковая панель и рабочая область.
- В стеклянном варианте shell прозрачен, имеет внешний отступ 10px и промежуток 10px; sidebar и рабочая область выглядят отдельными плавающими панелями.
- Sidebar: широкая версия 220px, компактная rail-версия 80px. Она сворачивается в колонку иконок; в развёрнутом, но не закреплённом состоянии может временно появляться поверх содержимого.
- Sidebar использует --k-blur-pane; у рабочей области скругление 22px, тонкий внутренний край и большая рассеянная тень.
- Topbar прозрачный, высотой 52px; строка статуса прозрачная, высотой 30px.
- Навигация имеет общий скользящий индикатор, а не набор несвязанных ярких плиток. Выбранный пункт — мягкая подложка, лаймовый маркер и акцентная иконка.
- Выбранный сервер/запуск использует собственный цветовой канал --c; активность показывается маленьким светодиодом и текстом состояния.

### 4.2. Карточки и панели

Общие карточки используют --k-surface, --k-r-card, --k-edge и --k-glass-shadow. В стеклянном слое у них, как правило, нет отдельной видимой границы. Между карточками применяется достаточно пространства, чтобы не создавать сплошную сетку рамок.

Для состояния внимания используется семантическая полоса/акцентный край. Например, предупреждение выделяется узкой янтарной полосой, а не полностью янтарной заливкой всей панели.

### 4.3. Кнопки

Базовая кнопка (.uiButton):

- минимальная высота 32px, горизонтальный padding 14px;
- шрифт UI 12px, средняя насыщенность;
- фон --k-raised, без жёсткой рамки, с --k-edge;
- скругление --k-r-ctl (10 px);
- hover слегка усиливает фон; активное нажатие кратко уменьшается до scale(.97).

Текущие значения hover/primary в glass.css:

- обычный hover-фон: color-mix(in srgb, var(--k-text) 12%, transparent);
- primary-градиент: linear-gradient(180deg, color-mix(in srgb, var(--k-accent) 86%, #fff), var(--k-accent));
- primary-тень: inset 0 1px 0 #ffffff60, var(--k-accent-glow);
- primary hover осветляет верхний слой до 76% акцента, добавляет 1px контур #c8f27c38 и тень до 8px.

Варианты:

- **Primary:** мягкий вертикальный лаймовый градиент, текст --k-accent-ink, лёгкий внутренний блик и слабое акцентное свечение. На hover кнопка приподнимается примерно на 1 px.
- **Danger:** прозрачная/нейтральная поверхность, красная подпись и полупрозрачная красная линия; hover добавляет мягкую красную подложку.
- **Danger ghost:** без постоянной рамки; красный текст и мягкая красная подложка при наведении.
- **Icon button:** нейтральная прозрачная кнопка; поверхность появляется при наведении. Использовать подсказку для неочевидной функции.
- **Кнопка отправки в композере:** круглая, 36×36px, лаймовая; выключенное состояние нейтральное.

Disabled состояние приглушается примерно до opacity: .5; элементы, которые нельзя нажать, не должны выглядеть активными.

### 4.4. Поля, селекты и переключатели

- Стандартные поля имеют минимум 30px высоты, padding 5px 9px, фон --k-bg, границу --k-line-2 и радиус 10 px.
- Фокус поля виден сразу: граница смешивает 70% --k-accent с прозрачностью, внешнее кольцо 4px использует --k-accent-soft, рядом появляется слабое свечение акцента. Сохранять системное :focus-visible кольцо для клавиатурной навигации.
- Placeholder использует --k-text-3.
- Многострочный пользовательский ввод набирается UI-шрифтом; моноширинный шрифт применять только к техническому коду или значениям.
- Выпадающий список имеет полупрозрачный фон, радиус 15 px, мягкую тень, выбранный пункт с акцентным tint. Если blur не поддержан, используется непрозрачный запасной фон.
- Переключатель имеет pill-форму примерно 38×22px, круглый белый бегунок 18px; включённое состояние использует --k-accent и сдержанное свечение.

### 4.5. Вкладки, сегменты, бейджи

- Группа вкладок/сегментов: утопленный контейнер с внутренней линией, padding около 3px, радиус 12–13px.
- Неактивный сегмент прозрачен; активный приподнят, получает --k-raised, внутренний край и лаймовую иконку.
- Обычный бейдж высотой 22px, короткий chip — 20px; в glass-слое оба обычно капсульные. Для статуса применяется мягкий фон и соответствующий цвет текста.
- Прогресс-трек тонкий (обычно 6px) и капсульный; заполнение может иметь очень слабое свечение того же цвета.

### 4.6. Сообщения и композер

- Сообщения имеют поверхность и внутренний край. Сообщение пользователя слегка подкрашено акцентом; его угол внизу справа меньше остальных (18px 18px 6px 18px).
- Кодовый блок получает отдельную сдержанную поверхность, внутреннюю тонкую границу и радиус около 12px.
- Chat composer — крупная рабочая поверхность с радиусом около 18px; текстовая область не выглядит обычным прямоугольным полем.
- Agent composer в актуальном desktop-стиле использует повышенную поверхность, радиус 20px, padding 16px, а при фокусе получает тонкий акцентный край.
- Панель модели, агента и уровня рассуждений остаётся компактной, чтобы не конкурировать с полем ввода.

### 4.7. Диалоги, меню и уведомления

- Диалоги, command palette, popover-меню, toast и другие крупные оверлеи используют --k-over-bg, --k-r-over, --k-shadow-over и --k-blur-over.
- Backdrop затемняет базу примерно на 45% и размывается на 6px.
- Command palette шириной до 680px: строка ввода высотой 56px, результаты по 38px, выбранная строка получает мягкий фон и левый/внутренний маркер.
- Toast имеет поверхность оверлея, пиктограмму по смыслу, опциональную кнопку-действие и тонкую линию времени жизни. Таймер останавливается при наведении/паузе.
- Когда backdrop-filter не поддерживается, фон становится сплошным. При prefers-reduced-transparency или prefers-contrast: more ambient field скрывается, а основные панели становятся непрозрачными.

### 4.8. Метрики и техническая информация

- Значения скорости, памяти, температуры, порты, endpoint и горячие клавиши используют --k-f-mono и табличные цифры.
- Линии сетки и разделители графиков остаются слабее данных.
- Палитра серии не должна случайно совпадать с цветом ошибки/предупреждения там, где это может спутать состояние и метрику.
- VRAM обозначается синим/циановым, RAM — мятным каналом.
- Цветовой сегмент памяти подписывается тёмным текстом в тёмной теме и белым в светлой через --k-run-ink.

### 4.9. Скроллбары и пустые состояния

Скроллбар тонкий, с прозрачной дорожкой и приглушённым округлым thumb. При наведении thumb светлеет; стрелки scrollbar скрыты, углы прозрачные.

Empty state использует спокойную иконку, короткий заголовок, понятное пояснение и при необходимости одно действие. Пунктирная граница и muted-текст остаются вторичными, чтобы пустое место не выглядело ошибкой.

## 5. Движение и обратная связь

Токены анимации из [motion.css](../../src/styles/kontur/motion.css):

| Токен | Значение | Использование |
|---|---|---|
| **--k-motion-press** | 60ms | Короткий отклик на нажатие |
| **--k-motion-fast** | 120ms | Hover и смена цвета/границы |
| **--k-motion-settle** | 220ms | Успокоение поверхности и теней |
| **--k-motion-enter** | 380ms | Появление полотна маршрута |
| **--k-motion-ease** | cubic-bezier(.16, 1, .3, 1) | Основное мягкое замедление |
| **--k-motion-spring** | cubic-bezier(.32, 1.28, .5, 1) | Навигация и появление оверлеев |
| **--k-ease** | cubic-bezier(.16, 1, .3, 1) в текущем стеклянном слое | Общие переходы |
| **--k-spring** | cubic-bezier(.32, 1.28, .5, 1) | Пружинный отклик |

В базовом tokens.css --k-ease равен cubic-bezier(.2, .8, .2, 1); слой glass.css заменяет его значением cubic-bezier(.16, 1, .3, 1).

Правила:

- наведение и фокус должны менять внешний вид немедленно; анимация только сглаживает визуальное установление;
- обычные кнопки и строки нажимаются быстро и слегка сжимаются;
- карточки действия/моделей при hover поднимаются максимум примерно на 2 px;
- смена маршрута — короткое появление с небольшим сдвигом и затуханием; верхние блоки могут входить каскадом с задержками 50–150 ms;
- ambient light дрейфует десятки секунд; активная генерация добавляет мягкое дыхание, но не мигает резко;
- индикаторы статуса могут пульсировать только при реальном переходе/работе;
- уважается prefers-reduced-motion: декоративные и входные анимации отключаются.

## 6. Плотность и адаптивность

Предпочтение плотности хранится как auto, comfortable или compact. В режиме auto используется compact, если ширина меньше 1500px или высота меньше 900px; в остальных случаях применяется комфортная плотность. Логика находится в [uiPrefs.ts](../../src/lib/uiPrefs.ts).

### Compact-переопределения

- --k-nav-h: 29px, --k-nav-gap: 1px, --k-pane-gap: 6px;
- --k-r-card: 13px, --k-r-ctl: 8px;
- размер основного текста 12.5px;
- brand 50px, topbar 44px;
- строки запуска получают меньшие вертикальные padding;
- стандартная страница: 12px 16px 16px;
- домашние секции сближаются, карточки становятся компактнее;
- базовые кнопки/поля уменьшаются до минимума 28px.

### Breakpoints стеклянного shell и экранов

- Высота до 820px: nav 31px, gap 2px, pane gap 8px, brand 54px; уменьшаются вертикальные отступы страницы и панели.
- Ширина до 1440px: command field 220px, уплотняется строка памяти.
- Ширина до 1360px: sidebar 208px, горизонтальный отступ контента 18px.
- Ширина до 1279px: часть кратких сведений о сервере и endpoint скрывается из верхней строки.
- Ширина до 1180px: sidebar 200px, pane gap 8px.
- Ширина до 1099px: поиск в topbar остаётся иконкой; некоторые сетки переходят в одну колонку.
- Ширина от 1900px: рабочий контент ограничивается шириной 1600px, боковые отступы страницы увеличиваются до 32px.

Компактный режим сохраняет те же цвета и контрастные роли; он уменьшает размеры и промежутки, а не создаёт отдельную визуальную тему.

### Локальные breakpoint-правила

- Workspace агентов скрывает подписи сегментированных кнопок при ширине центральной колонки до 1240px и подпись кнопки новой задачи до 760px.
- Agent composer до 1550px скрывает имя агента и ограничивает выбор модели шириной 300px; до 1050px раскладывает controls в несколько строк.
- Внутри композера при ширине контейнера до 600px скрывается имя агента и ограничивается ширина текста модели.
- Домашняя сетка перестраивается до одной основной колонки при viewport 1200px; до 900px список действий и боковые панели становятся одноколоночными.

## 7. Доступность и состояние ошибок

- :focus-visible — контур 2px цвета --k-focus с отступом 2px.
- Выделение текста использует отдельную синеватую подложку --k-selection-bg.
- Цветной статус всегда сопровождается текстовой подписью или формой индикатора.
- Ошибки используют --k-danger и --k-danger-soft; предупреждения — --k-warn и --k-warn-soft; информационные состояния — --k-info и --k-info-soft.
- Ошибка и восстановление — отдельные мягко окрашенные баннеры с объяснением и доступным действием.
- Поддерживаются уменьшение движения, повышенный контраст и выключенные системные эффекты прозрачности.
- Disabled не полагается только на цвет: он также использует disabled, приглушение и недоступный курсор.

## 8. Динамические CSS-параметры

Это локальные параметры компонентов, а не глобальные цветовые токены. Их значения задаются логикой или inline-стилями:

| Параметр | Назначение |
|---|---|
| **--c** | Цвет конкретного запуска/серии/активного действия |
| **--x**, **--y** | Положение ambient aura |
| **--d** | Период движения конкретной aura |
| **--o** | Базовая прозрачность aura |
| **--nav-i** | Индекс выбранной вкладки для позиции скользящего индикатора |
| **--aw-side** | Адаптивная ширина навигатора workspace агентов |
| **--toast-ms** | Длительность таймера уведомления; CSS fallback — 6000ms |
| **--aplot-popup-height** | Рассчитанная высота popover-селектора; CSS fallback — 320px |
| **--k-zoom** | Коэффициент CSS zoom в browser preview; --k-vh компенсирует его для высоты окна |

Формула базовой высоты shell: --k-vh = calc(100vh / var(--k-zoom, 1)). В Tauri используется webview zoom, поэтому --k-zoom обычно не задан; в browser preview CSS zoom компенсируется этой формулой.

Базовая ambient aura ставится в точку (8%, 6%), имеет цвет #2f4a57 и прозрачность .7 в тёмной теме; в светлой — #b7cfb0 и .9. Четыре точки aura запусков: (78%, 18%), (22%, 88%), (92%, 82%) и (46%, -6%). Обычная aura запуска получает цвет --c и прозрачность по умолчанию .55; при генерации повышается до .85. Период drift для запусков равен 38 + 9 × index секундам; базовая aura движется 60 секунд. Радиальный градиент aura смешивает 60% её цвета в центре и 18% на половине радиуса, растворяясь примерно к 72%. Нижний горизонт затемняет последние 40% viewport к --k-base. Overlay backdrop использует blur(6px) saturate(.9). Слой --k-grain задаёт слабую текстуру поверхности.

--aw-side в workspace агентов вычисляется как clamp(236px, 17vw, 292px). Положение и цвет aura задаются по активным запускам; не назначать для них фиксированный декоративный цвет.
