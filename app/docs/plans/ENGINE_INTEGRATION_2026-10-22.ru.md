# Интеграция llama.cpp и Strata — 22.10.2026

llama.cpp и Strata работают как локальные runtime, которыми владеет приложение. Rust backend подготавливает проверенные параметры, запускает движок, управляет жизненным циклом и предоставляет интерфейсу состояние, логи, метрики и подключение чата. Это полноценная управляемая интеграция через локальный API. Код GPU-движка не линкуется внутрь процесса интерфейса.

Раздельный процесс нужен для независимых запусков, изоляции ошибок драйвера и освобождения памяти при остановке модели. В случае Strata собственный Python сервер запускает нативный inference executable. Приложение владеет этим деревом целиком. Компоненты устанавливаются в локальные каталоги; веса и настройки моделей остаются отдельными файлами.

## Проверенная архитектура

| Задача | Реализация |
| --- | --- |
| Установка, поиск и версии компонентов | `components.rs`, `component_maintenance.rs`, `installer/` |
| Проверка движка и его параметров | `engine_adapters.rs`, `strata.rs`, `models.rs` |
| Запуск, отдельные слоты и поколения процессов | `runs.rs`, `process.rs` |
| Собственное дерево процессов Windows | `owned_job.rs` |
| Порты, остановка, перезапуск и обработка падения | `runs.rs`, `process.rs`, `app_lifecycle.rs` |
| Реальные health/metrics/slots, RAM и GPU | `runtime.rs`, `llama.rs`, `process_memory.rs`, `hardware.rs` |
| Чат с конкретной моделью и поколением | `runs.rs`, `chat.rs` |
| Встроенное окно Web UI движка | `web_ui.rs` и bootstrap соответствующего движка |

Два движка имеют разные адаптеры. Параметры llama.cpp не переносятся в Strata автоматически. Native router разрешён только для llama.cpp. Перезапуск использует параметры активного запуска; изменение глобальных настроек не подменяет конфигурацию уже работающей модели.

## Исправления

1. Каждый inference runtime получил собственный Windows Job с `KILL_ON_JOB_CLOSE`. Ранее такие jobs использовались у агентов, но не у самих движков. Теперь уничтожение владельца или освобождение слота упавшего Python сервера также завершает его нативных потомков. Если назначение в job не удалось, запуск откатывается с понятной ошибкой. Jobs разных запусков независимы.
2. Перед созданием процесса проверяется доступность выбранного bind-порта. Занятый сторонним сервисом порт отклоняется до запуска: приложение не успевает принять чужой `/health` за состояние своей модели. Автоматический выбор свободного порта сохраняется. Между проверкой и bind самого движка остаётся обычная системная гонка; окончательный результат также определяется жизненным циклом процесса.
3. Bind-адреса `0.0.0.0` и `::` преобразуются соответственно в `127.0.0.1` и `::1` для локальных health, metrics, chat и Web UI запросов. Аргумент `--host` движка сохраняется, поэтому доступ по локальной сети продолжает работать.
4. Подготовка команды Strata и метаданных модели использует один проверенный JSON. Путь нативных весов теперь разрешается против `config.cwd`, как у самого движка. Ранее защита файлов активной модели ошибочно использовала рабочий каталог Python. Устаревшие `resolvedModelPaths` удаляются и для конфигураций без единственного файла весов.
5. Отсутствующий рабочий каталог Strata и элементы `args`, которые не являются строками, отклоняются до запуска.
6. Ошибка запуска называет реальный backend; ошибка создания/назначения Windows Job содержит системную причину и не теряет созданный handle.

## Проверки

Команда:

```powershell
cargo test --lib --target-dir C:\Dev\Aplot-Control-LLM\local\builds\next-version
```

Результат на снимке изменений: **207 passed, 0 failed, 7 ignored**. Проверки, требующие реальных моделей/сети, по умолчанию пропущены.

Новые и существующие регрессионные проверки покрывают:

- Настоящие Windows процессы `cmd.exe → ping.exe`: освобождение владельца закрывает всё дерево; другой принадлежащий приложению запуск продолжает работать.
- Принудительное завершение процесса-обёртки с последующей штатной очисткой: нативный потомок завершается.
- Отказ запуска при занятом внешнем порте до попытки spawn; сторонний listener остаётся активным.
- IPv4/IPv6 wildcard endpoints и сохранение исходного bind host.
- Метаданные и защита Strata весов при отдельном native cwd, удаление устаревшего пути, раннее отклонение неверных конфигураций.
- Изоляцию параллельных запусков, автоматические порты, состояние падения и корректное завершение процессов.

Реальная генерация на моделях в эту итерацию не запускалась. Проверки создавали только собственные короткоживущие процессы и временные конфигурации; существующее приложение и рабочие серверы пользователя не останавливались.

Стандартный `src-tauri/target` содержит старые абсолютные пути Tauri после переноса репозитория. Для проверки использован уже существующий актуальный `local/builds/next-version`; старый кэш не удалялся.
