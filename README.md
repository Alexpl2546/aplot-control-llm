# Aplot Control LLM

**Русский** · [English](README.en.md)

Aplot Control LLM — приложение для Windows, которое помогает запускать локальные языковые модели и управлять их настройками. Вместо набора команд и отдельных окон — общая библиотека моделей, сохранённые профили, графики нагрузки и журналы сервера.

Поддерживаются только два локальных движка: **llama.cpp** и **Strata**. Aplot запускает их, управляет настройками и наблюдает за работой. В библиотеку можно скачать GGUF из публичного Hugging Face Hub; установка бинарников движков остаётся отдельным шагом.

В этой рабочей установке веса хранятся в `models/`. [Каталог моделей](docs/MODEL_STORAGE.md) показывает точные пути, общие файлы, размеры и порядок удаления.

## Что можно делать

- **Запускать и останавливать сервер** из одного окна, видеть его адрес и состояние.
- **Вести библиотеку моделей** из нескольких папок, находить GGUF, скачивать его из Hugging Face, фильтровать по движку и добавлять модели в избранное.
- **Сохранять профили запуска:** модель, размер контекста, параметры памяти и другие настройки. Профили можно копировать, импортировать и экспортировать в JSON.
- **Наблюдать за нагрузкой:** CPU, RAM, NVIDIA GPU, скорость генерации, обработка запроса, время до первого токена и использование контекста. Набор показателей зависит от движка.
- **Настраивать главную страницу:** перемещать и менять размер карточек, выбирать графики, сохранять расположение.
- **Сравнивать настройки в бенчмарках.** Для llama.cpp есть автоматический поиск профилей с большим контекстом, высокой скоростью и балансом между ними.
- **Подключать другие приложения** к API локального сервера. В режиме роутера llama.cpp модель выбирается по имени сохранённого профиля.

Интерфейс доступен на русском и английском. Есть светлая и тёмная темы, работа в трее и настройки автозапуска.

## Какой движок выбрать

| Движок | Что используется в Aplot | Что нужно установить |
| --- | --- | --- |
| **llama.cpp**[^llama] | GGUF, подробные параметры запуска, профили, метрики, бенчмарки и нативный роутер моделей | Сборку с `llama-server.exe`, подходящую вашей видеокарте или CPU. Для роутера нужна поддержка `--models-preset`, `--models-max` и автозагрузки моделей |
| **Strata**[^strata] | Подготовленные конфигурации `strata-*.json`, запуск сервера, мониторинг и тесты контекста | Рабочую установку Strata с Python-окружением, токенизатором, движком и моделью |

Один GGUF может подходить нескольким движкам, но совместимость не универсальна. Файл проектора для изображений и дополнительный шард нельзя запускать как самостоятельную модель. Aplot проверяет такие случаи перед запуском.

Автоматический подбор параметров работает только с llama.cpp. Точные тесты контекста требуют API подсчёта токенов у сервера. Для используемой нами Strata эти дополнения сохранены в [отдельном патче](integrations/strata/README.md).

## Быстрый старт

### Готовое приложение

Скачайте установщик или приложение из [GitHub Releases](https://github.com/Alexpl2546/aplot-control-llm/releases). Если готового релиза ещё нет, используйте [сборку из исходников](#сборка-из-исходников).

1. Установите llama.cpp или Strata по инструкции в репозитории — ссылки приведены в таблице выше.
2. В библиотеке нажмите **Скачать модель**, вставьте ссылку Hugging Face или `owner/repository`, выберите полный GGUF-вариант и папку назначения. Файлы появятся в библиотеке после проверки. Для Strata отдельно подготовьте конфигурацию `strata-*.json` и tokenizer.
3. Запустите Aplot и выберите llama.cpp или Strata. Укажите путь к установке и модели/конфигурации, если мастер ещё не настроил их.
4. Выберите модель или подготовленную конфигурацию, задайте параметры и запустите сервер.
5. Дождитесь состояния готовности. Адрес сервера будет показан на главной странице; его можно использовать в API-клиенте.

Для обычного запуска не нужны Node.js и Rust. Они нужны только для сборки приложения. Модели, DLL движков и их зависимости в установщик Aplot не входят.

### Требования

Проверенная платформа — **Windows 11 x64** с WebView2 Runtime. Другие ОС пока не подтверждены для настольной версии.

Объём RAM, VRAM и необходимость CUDA зависят от модели и сборки движка. Для показателей NVIDIA нужен `nvidia-smi`, обычно устанавливаемый вместе с драйвером. Оценка памяти в интерфейсе ориентировочная: окончательное решение о размещении модели принимает движок.

### Подключение API-клиента

В клиенте с поддержкой OpenAI API укажите фактический адрес запущенного сервера с суффиксом `/v1` и имя модели из `/v1/models`. Порт берите из Aplot: он может отличаться от примера.

В роутере llama.cpp имя модели — это имя профиля Aplot. Передайте настроенный API-ключ, если сервер требует авторизацию. Поддержка конкретных методов, изображений и tool calls зависит от модели и версии движка; справка API в приложении помогает проверить доступные возможности.

## Сборка из исходников

Понадобятся Git, **Node.js 22.12+**, npm, стабильный Rust с инструментарием MSVC, Visual Studio Build Tools с компонентом **Desktop development with C++**, Windows SDK и WebView2. Подробности — в [инструкции для Windows](app/docs/WINDOWS_BUILD.md).

```powershell
git clone https://github.com/Alexpl2546/aplot-control-llm.git
cd aplot-control-llm/app
npm ci
npm run tauri:dev
```

`npm ci` устанавливает версии из `package-lock.json`. Первый запуск Cargo загрузит зависимости Rust и может занять несколько минут. Установка движков для компиляции Aplot не требуется.

Для готового приложения и установщиков:

```powershell
npm run tauri:build
```

Исполняемый файл появится в `app/src-tauri/target/release/`, установщики — в `app/src-tauri/target/release/bundle/`.

Команда `npm run dev` открывает интерфейс в браузере с демонстрационными данными. Управление настоящими процессами и модели доступны в настольном режиме `tauri:dev` или в собранном приложении.

### Проверки перед коммитом

Из папки `app`:

```powershell
npm run build
npm test
npm run verify:source
python -m unittest discover -s tests -p "test_*.py"
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo test --locked --manifest-path src-tauri/Cargo.toml
cargo check --locked --manifest-path src-tauri/Cargo.toml
```

Python нужен только для проверки вспомогательного импортера профилей. GitHub Actions проверяет интерфейс и сборку Windows при push и pull request. Работа реальной модели, драйверов и трея дополнительно проверяется вручную.

## Где хранятся данные

Настройки, профили и результаты бенчмарков записываются в SQLite. Если приложение находится внутри папки с каталогами `engines` и `models`, оно использует `data/llama-control.sqlite3` в этой папке. Иначе данные хранятся в `%APPDATA%\app.aplot.llamacontrol`.

При запуске создаётся резервная копия базы. Для переноса профилей между компьютерами удобнее JSON-экспорт: пути к моделям на новом компьютере нужно проверить. База и экспортированные профили могут содержать API-ключи — не публикуйте их вместе с отчётом об ошибке.

Модели и движки можно хранить вне папки проекта. Каталоги `models`, `engines`, `data`, локальные отчёты, сборки и резервные копии исключены из Git; `package-lock.json` и `Cargo.lock` включены для воспроизводимой сборки.
