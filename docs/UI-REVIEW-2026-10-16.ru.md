# Правки интерфейса и встроенный чат — 16 октября 2026

## По аннотациям

- RAM и VRAM: вместо серой штриховки используется сплошная заливка. Длина заполнения соответствует измеренному объёму. VRAM — голубой, RAM — бирюзовый; цвета адаптированы для светлой темы. Известные доли серверов сохраняют собственные цвета.
- Убраны подпись под «Обзором», пояснение рядом с заголовком памяти и длинный текст про отсутствие оценки для отдельных моделей. Пояснения об измерении и оценке доступны в подсказке блока памяти. Предупреждения о масштабировании оценок сохранены.
- Палитра серверов заменена на голубые, бирюзовые, янтарные и зелёные оттенки. Подписи CH1/CH2 в оболочке, карте памяти и командном меню заменены на «Сервер 1/2» (Server 1/2).
- Выбор запуска, движка, профиля и кнопка запуска находятся на одной линии; на узких экранах переносятся сеткой. Выбор доступен сразу, без раскрытия технического блока. При выборе движка подбирается сохранённый профиль этого движка, если он имеется. Выбор профиля использует существующий механизм отдельных запусков. Работающие серверы автоматически не перезапускаются.
- Поле сценария и поля выбора запуска используют общий тематический компонент ChoiceSelect: стрелки, Home/End, Enter/Space, Escape, поиск по первой букве, закрытие при уходе фокуса или клике снаружи.
- Исправлено смещение строк компактного sidebar при раскрытии наведением: ранее оно могло приводить к нажатию соседнего пункта.

## Встроенный чат

В основной навигации добавлена вкладка «Чат». Кнопка «Открыть чат» на главной открывает её для выбранного сервера. Интерфейс приложения не загружает страницы llama.cpp или Strata; существующий API сервера продолжает работать независимо.

Поддерживается текстовый диалог с потоковым ответом, остановка генерации, новый диалог, копирование ответа, раскрываемые рассуждения и безопасный вывод блоков кода. Enter отправляет сообщение, Shift+Enter добавляет строку. При остановленном сервере отправка недоступна.

Диалоги разделены по идентификатору и поколению запуска. Перезапуск начинает новую историю, переключение серверов не смешивает сообщения. История хранится в памяти до закрытия приложения. Уход со вкладки или смена сервера во время генерации отменяет запрос. Изображения, вложения, инструменты и постоянное хранение истории в эту первую версию не входят.

Запрос проходит через нативные команды `chat_send` / `chat_cancel`. Адрес, API-ключ и реальный идентификатор модели определяются из зарегистрированного запуска через существующий механизм подключения. Ключ не передаётся в новую страницу или URL. Нативная часть следит за поколением запуска, отменой и лимитами сообщения; HTTP-ошибки возвращаются без тела ответа и секретов. Используется OpenAI-совместимый `POST /v1/chat/completions`, `stream: true`. Неподдерживаемый API отображает явную ошибку.

Температура и бюджет ответа берутся из снимка профиля задачи, когда он имеется; иначе используются температура профиля и базовый бюджет до 4K токенов с ограничением по контексту. Остальные параметры остаются серверными настройками. Это текстовый клиент; автоматически переносить все инструкции Smart Task Profiles в системное сообщение он пока не умеет.

## Исправление выбора запуска после проверки на настоящих профилях

Выбор профиля ранее вызывал `focusProfileRun`, который добавлял в список искусственную остановленную сессию до запуска. Теперь этот метод выбирает только существующий запуск; новый профиль остаётся черновиком с подписью «Новый запуск». Новая сессия появляется после явного Start. Обнулены показатели предыдущего сервера при переходе к черновику, сохранены работающие запуски и их снимки параметров. Двойное нажатие Start во время подготовки блокируется и для черновика без выбранного сервера.

Вторая ошибка: проверка готовности Strata требовала буквального совпадения пути со списком обнаружения. Сохранённые JSON использовали повторные разделители, а Windows возвращала канонические пути с `\\?\`. Файлы при этом существовали. Добавлено общее сравнение Windows-путей; исправлены поиск модели, контекста и начального профиля. Готовность запуска больше не зависит от наличия строки в списке обнаружения: отсутствие обязательного параметра имеет конкретную причину, а нативная подготовка проверяет сами файлы.

Повторный выбор того же движка или профиля не меняет состояние. При переходе к другому движку обновляются обнаруженные модели и, для llama.cpp, возможности выбранного бинарника.

Проверено 283 frontend-теста (43 файла), TypeScript, статическая проверка, границы модулей, production build и Windows EXE. Новые регрессии покрывают пустой список, многократный выбор Strata-профилей до Start, сохранность уже работающих серверов, запрет повторного Start и варианты путей Windows. В браузере выбор нового профиля сохранил два исходных сервера и активировал Start; третий появился только после Start. Повторный выбор Strata не изменил число серверов. Реальная генерация Flash Next в этом исправлении не запускалась.
