# Встроенный Hermes — первая версия

Реализовано 17 октября 2026 года в Aplot Control LLM 0.8.2.

## Как попробовать

1. Запустить сервер модели с контекстом не меньше 64K. У установленного Hermes это обязательный минимум; Aplot не изменяет профиль автоматически.
2. Открыть «Чат» → «Агент Hermes» и выбрать сервер.
3. Нажать «Рабочая папка» и выбрать каталог задачи.
4. При необходимости раскрыть «Инструменты и skills» и подключить каталог, содержащий папки навыков с SKILL.md.
5. Написать задачу. Действия инструмента раскрываются для просмотра аргументов и результата. Уточнения и разрешения появляются в диалоге.

Hermes CLI должен быть установлен в поддерживаемом каталоге %LOCALAPPDATA%/hermes/hermes-agent с venv/.venv. Hermes Desktop не требуется. Существующее внешнее подключение через кнопку «Открыть в Hermes» сохранено.

## Что включено

- Настоящий Hermes Agent через фоновый TUI Gateway JSON-RPC по stdin/stdout, без терминального окна или окна Desktop.
- Подключение к фактической модели выбранного native run_connection, включая серверную авторизацию и контекст.
- Файлы, терминальные команды, skills, память, план задач и clarify. До 20 агентных шагов и 600 секунд на запрос.
- Постепенный вывод ответа и рассуждений, лента действий, результаты инструментов, уточняющие вопросы.
- Ответ на approval: «Разрешить один раз» или «Отклонить». Постоянное разрешение и автоматическое согласие клиентом не поддерживаются. Запросы, которых клиент не умеет обрабатывать, получают явный отказ в поддержке.
- Остановка текущей задачи и отдельное завершение процесса агента. Остановка во время запуска не отправляет отложенный запрос после нажатия кнопки.
- Генерация принадлежит диалогу, а не React-странице. Переключение разделов и серверов не отменяет её. Запрос и ответ на разрешение проверяют поколение сервера; фоновая проверка также закрывает агента при остановке/перезапуске модели.
- RU/EN, тёмная и светлая темы, существующие компоненты «Контура». Горизонтальное переполнение при ширине 1280 px не обнаружено.

Рабочая папка задаёт cwd; это не песочница доступа к файлам. Инструменты работают с правами пользователя. Правила Hermes определяют, какие команды требуют approval; это не подтверждение каждой записи файла или каждого действия.

## Данные и ограничения первой версии

Каждый встроенный диалог имеет собственный HERMES_HOME в каталоге данных Aplot: hermes-conversations/<UUID>. Конфигурация внешнего Hermes Desktop не импортируется и не изменяется. История и память сохраняются Hermes на диске отдельно для этого диалога; экран восстановления после перезапуска Aplot пока не реализован. Новый диалог сохраняет выбранные пути рабочей папки и skills, но создаёт отдельную историю и память.

API-ключ передаётся Python через stdin и остаётся в приватной конфигурации провайдера диалога Hermes. В аргументы процесса и события интерфейса он не включается. Вывод маскируется; служебные идентификаторы протокола не изменяются при маскировании даже коротких ключей. stderr runtime не выводится в интерфейс. URL и model ID не принимаются от UI: их разрешает Rust через выбранный сервер.

Параллельно допускается до четырёх процессов встроенных диалогов, по одному запросу на диалог. Закрытый или аварийно завершённый диалог требует «Новый диалог»; нельзя показывать старую историю как контекст нового runtime. При обычном выходе Aplot завершает принадлежащие ему деревья процессов агентов; закрытие в трей подчиняется существующим настройкам приложения.

Параметры отдельных запросов Smart Task Profiles ещё не отображены на настройки Hermes: используются его собственные параметры генерации и контекст работающего сервера. Автоматический переход на запасной провайдер в конфигурации отключён. Способность вызывать инструменты зависит от модели и её движка.

MCP-настройки, магазин навыков, импорт истории Desktop, восстановление сессий при запуске и управление компьютером не входят в первую версию. Подключение папки skills реализовано. Рассуждения агента показаны в исходном виде; ручной перевод обычного чата сохранён, в агентный режим его кнопка пока не перенесена.

## Проверки

Полная история функции: переключатель чата → native-команда → отдельный Python Hermes → API модели → инструмент/интерактивный запрос → обновление интерфейса.

- TypeScript, verify:source, verify:modules: успешно. Отдельной команды ESLint в проекте нет; использованы существующие статические проверки.
- 322 frontend-теста, включая владение фоновой задачей, запоздалые события, отмену во время запуска, состояния вопросов, частичный ответ при потере runtime и повторный запрос после Stop в предпросмотре.
- 134 Rust-теста успешно, семь штатно пропущены. Добавлены проверки разрешений и маскирования ключей без повреждения идентификаторов. Существующая интеграционная проверка Rust также прошла.
- Настоящий установленный Hermes в изолированном временном home с локальным тестовым OpenAI API: загрузка skill из внешней папки, чтение файла, clarify с ответом, approval с отказом, сохранность файла после отказа, следующий запрос в той же сессии. Отдельно проверены session.interrupt во время ожидания clarify, событие request.cancel и итоговый статус interrupted. Облачные запросы в этой проверке не используются. Тест: app/tests/hermes_agent_runtime_test.py.
- Production EXE запущен через Windows UI. На Flash Next IQ3_S · 128K · Strata из встроенного чата вызван read_file, прочитан README.txt тестовой папки и получена контрольная строка «Лаймовый контур 47», которой не было в пользовательском запросе. Во время работы выполнен переход на главную и возврат в чат.
- Второй запрос в том же native-диалоге вызвал clarify. В форме выбран ответ «Да», после отправки агент продолжил и написал: «Подтверждаю: вы ответили „Да“ — проверку продолжаем».
- Dark/RU и Light/EN проверены в браузерном предпросмотре; там данные и ответы явно обозначены демонстрационными. Native-проверка выше выполнена отдельно на настоящем сервере.

Артефакты: app/artifacts/hermes-agent-v1/. Снимок реального чтения файла: agent-native-read.jpg. Рабочая тестовая папка: workspace/README.txt. Результаты не являются сравнением качества моделей или замером скорости.

Итоговый EXE: app/src-tauri/target/release/aplot-control-llm.exe, сборка npx tauri build --no-bundle успешна. Тестовый native-сеанс оставлен открытым; чтобы загрузить последние поправки формы вопросов, нужно полностью выйти из Aplot через трей и открыть итоговый EXE. Запущенная во время проверки предыдущая сборка сохранена как aplot-control-llm.before-agent-final-2026-10-17.exe.

## Следующее развитие

Восстановление диалогов и общая память по проекту; список подключённых skills и их включение; MCP; отображение параметров Smart Task Profiles с проверкой поддержки; понятная диагностика несовместимого runtime; экспорт истории. Каждый пункт можно добавлять отдельно поверх текущего менеджера процессов и транспорта.
