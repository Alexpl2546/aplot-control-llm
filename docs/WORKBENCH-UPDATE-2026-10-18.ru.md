# Обновление рабочей среды Aplot — 18 октября 2026

## Изменения оболочки

- «Главная» стала началом работы: запуск модели, диалог, агент, последние задачи и проекты. Большие графики перенесены в «Производительность».
- «Рабочая среда» объединяет обычный чат и Agent Workspace. Сейчас доступен Hermes; другие агенты не имитируются.
- «Производительность» содержит вкладки «Мониторинг» и «Бенчмарки». Перенесены существующие виджеты, карта памяти, диапазоны времени и редактор раскладки. Настройки и результаты не мигрируются в новый формат и не сбрасываются.
- Правый клик по серверу или Shift+F10 открывает действия: запуск, остановка, перезапуск, параметры, рабочая среда, технический журнал, адрес API и обновление состояния. Доступность определяется фактическим состоянием и владением сервером.
- Плюс открывает небольшое окно выбора движка и готового профиля. Выбор остаётся локальным черновиком окна. Создание/запуск выполняется только по кнопке. Уже работающий профиль открывает существующий сервер.
- Компактная панель расширена до 80 px: индикатор состояния и S1/S2. Под серверами видны активные сессии Hermes, включая ожидающие пользовательского решения; завершённая история не выдаётся за работающий процесс.
- Исправлено повторное открытие ChoiceSelect после выбора пункта внутри label.

## События и диагностика

По умолчанию открываются «События»: состояние серверов и агентов сейчас, затем история жизненного цикла, сохранения профилей, инструментов, решений по разрешениям и смены режима доступа. Есть поиск, фильтр источника и фильтр требующих внимания событий.

Это структурированные события приложения, а не пересказ LLM. Переходы ready ↔ busy для каждого запроса и поток токенов не засоряют историю. Старые transcript-инструменты при восстановлении не записываются как заново выполненные.

История хранится в существующей SQLite-таблице events отдельно под activity.v1: до 2000 записей на диске, последние 500 в интерфейсе. Ошибка сохранения отображается. История начинается с обновления; старый stdout автоматически не реконструируется в события.

«Технический журнал» сохраняет прежние фильтры INFO/WARN/ERROR/DEBUG, поиск, паузу, экспорт и очистку. Команда из меню сервера выбирает нужный сервер перед открытием журнала.

## Вложения и речь

В панели ввода Hermes появились файлы, изображения и голос. Файлы можно выбрать системным диалогом; изображения — также вставить из буфера, файлы — перетащить в поле ввода. Вложения показаны до отправки и в истории пользовательского сообщения. Ограничение: 8 файлов по 25 МиБ. В SQLite сохраняются метаданные и пути, а не base64 всего файла. Если исходный файл удалён или перемещён до отправки, ошибка не уничтожает черновик.

Файлы передаются через file.attach с ref_text, изображения — через image.attach. Для изображений включена нативная передача image_url. Понимание изображения зависит от выбранной модели; неподдерживаемая модель может отклонить запрос. Произвольные бинарные файлы не становятся автоматически читаемыми документами.

Голос использует установленный Hermes, sounddevice и локальный faster-whisper: модель base, CPU/int8, язык ru. При первом использовании загружаются веса ASR; обработка речи затем выполняется локально. Текст поступает в черновик и отправляется только пользователем. Микрофон и зависимости на другом ПК могут потребовать настройки. Звукозапись с реального микрофона пользователя при автоматической проверке не запускалась.

На Windows optional NumPy/sounddevice предварительно импортируются в основном потоке bootstrap: устранено зависание первой загрузки DLL внутри RPC-потока голоса. Это не включает микрофон и не загружает модель распознавания при обычной переписке.

## Контекст текущего чата

Индикатор использует session.context_breakdown и session.usage выбранной Hermes-сессии. Не используется накопительный счётчик токенов за все запросы. По клику доступны системный промпт, определения инструментов, правила, навыки, MCP, определения подагентов, память и диалог с результатами инструментов — в тех категориях, которые реально возвращает Hermes.

Общий итог может быть измерен провайдером, привязан к измерению с добавленной оценкой или полностью оценён локально. Разбивка категорий приблизительная и помечена отдельно. После перезапуска приложения сохранённые цифры являются снимком старой сессии. До измерения отображается неизвестное значение, а не вымышленный ноль.

## Доступ и постоянные разрешения

- «С разрешениями»: approvals.mode=manual. Hermes запрашивает согласие на действия, которые его проверка считает требующими подтверждения.
- «Полный доступ»: approvals.mode=off для доступных инструментов. Действия выполняются с правами приложения; это не повышение привилегий Windows.
- «Без терминала»: из набора исключён терминал и управление процессами. Файлы всё ещё можно читать и изменять; это не read-only и не sandbox.

Manual/full переключаются через настоящий config.set для текущей сессии. Смена набора инструментов требует новой сессии; отображается действующий режим и соответствующая кнопка. Уже открытый запрос разрешения требует отдельного ответа.

Кнопки «На эту сессию» и «Всегда» появляются, только когда их предлагает Hermes и позволяет его область разрешения. Нативный мост также проверяет этот список. Постоянные правила сохраняются в частном HERMES_HOME задачи, привязанном к UUID задачи, и переживают обновление bootstrap при новой сессии или смене модели. Правило может относиться к категории команд Hermes, а не только к точному тексту одной команды. Глобальные настройки Hermes Desktop не меняются.

## Исправление запуска из сохранённой задачи

- Для отключённой задачи добавлено действие «Запустить модель задачи». Окно быстрого запуска выбирает её сохранённый профиль по ID и движку. Создание сервера происходит после явного нажатия «Запустить».
- Сохранённая связь без существующего сервера подписана «Сохранённое подключение»; номер несуществующего сервера больше не выводится.
- Переход к параметрам профиля задачи сначала выбирает именно её профиль. Если профиль удалён или сменил движок, интерфейс сообщает об этом и предлагает выбрать другой сервер; совпадение названий не считается совпадением профилей.
- Для llama.cpp проверяется фактически запускаемый бинарный файл, поэтому предварительно открывать настройки и нажимать «Обнаружить» больше не требуется. Результат проверки не берётся от ранее выбранного бинарника. Strata и другие движки эту проверку не проходят.
- При изменении параметров перезапуска проверка нового бинарника выполняется до остановки действующего сервера.
- Восстановление истории по-прежнему не означает восстановления процесса Hermes: после готовности сервера пользователь создаёт новую сессию с явной передачей контекста.
