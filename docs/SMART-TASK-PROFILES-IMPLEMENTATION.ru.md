# Smart Task Profiles: реализованный Control Desk

Дата: 14 октября 2026. Основа: [утверждённая концепция](SMART-TASK-PROFILES-CONCEPT.ru.md), [«Контур»](CURRENT-UI-DESIGN.ru.md) и референс Control Desk — Simplified.

## Что доступно

В разделе «Параметры запуска» появились вкладки «Под задачу» и «Параметры движка». Во второй сохранён существующий редактор каждого backend. Глобальная навигация и оболочка не менялись.

Новый экран содержит пять категорий, специализированные сценарии в списке, четыре регулятора, приоритет, рекомендацию и максимум две альтернативы. Подробности sampler, инструкции клиенту и ресурсная проверка раскрываются отдельно. Все цвета используют существующие роли «Контура», а новые пользовательские строки находятся в RU/EN-ресурсах.

## Логика

- «Свобода решений» меняет температуру и top_p в плане запроса. Qwen3.6 / Strata с рассуждением использует отдельный рецепт; старт для кодинга — 0.6. Для общего прямого coding-пресета — 0.2.
- «Объём задачи» выбирает 8K/16K/32K/64K/128K. «Авто» берёт бюджет сценария; приложение не получает файлы внешнего клиента и не заявляет точного подсчёта его входа.
- «Глубина» влияет на request recipe Qwen3.6 / Strata; для остальных комбинаций доступен экспорт инструкции, без изменения существующего reasoning-режима движка.
- «Подробность» меняет лимит max_tokens; для базового кодинга уровень 3 даёт 4096 токенов. Экспортируемая инструкция выражает желаемую подробность словами.
- Модель можно закрепить; при недостаточном контексте появляется конфликт. Температуру можно закрепить отдельно. Выбор нового сценария сохраняет закрепления.
- Черновики разделены по run/editor и хранят только смысловые значения и ID, без API-ключей. Повреждённые значения из localStorage отбрасываются.
- Приоритет меняет предварительный порядок подходящих сохранённых профилей. Это качественная рекомендация по существующему обзору и пригодности семейства, без вымышленного coding/design score.
- Изменение регуляторов не запускает/не переключает модель и не меняет глобальные engine settings.

## Применение

«Применить настройки» создаёт отдельный производный профиль, сохраняя исходный и его рабочие параметры. Native v2 duplication сохраняет защищённые ссылки на секреты и проверяет revision; новый профиль не помечается last-known-good. Работающие серверы и их router presets не обновляются автоматически.

Для Strata native-команда создаёт отдельный `strata-task-<UUID>.json` в проверенном корне установки. Разрешено только уменьшение контекста относительно исходного JSON. MTP, env, KV и бюджеты экспертов сохраняются. Имя ограничено UUID-подобным идентификатором, файл создаётся без перезаписи; ошибки сохранения откатывают производный файл и дубликат профиля.

Для llama.cpp учитывается общий KV-пул: выбранный контекст на запрос умножается на сохранённую параллельность. Infernix, QwFNfer и Ollama получают контекст в своих settings snapshots. У Infernix/QwFNfer также поддержаны плоские engine options импортированных native-профилей.

Перед native-сохранением существующий ресурсный planner проверяет точный производный запуск. Явное `insufficient` блокирует сохранение. `unknown` не объявляется гарантией успешного запуска; окончательную загрузку контролируют существующие lifecycle/engine checks. Ресурсный preview в Strata до применения явно относится к исходному JSON.

Сохранённый task-профиль выбирается как новый остановленный запуск. Его запуск выполняется существующими действиями на главной. Другие каналы продолжают работать. Если пользователь переключил канал, пока профиль сохранялся, результат добавляется в библиотеку и не перехватывает новый выбор.

## Параметры клиента и статусы

Внешний клиент автоматически не перенастраивается. В технических подробностях доступны отдельные действия копирования параметров запроса и инструкции. Model ID нужно брать из API-раздела фактического запуска. Избыточный reasoning budget не выделяется отдельно поверх max_tokens: общий лимит включает рассуждение.

У llama.cpp temperature/top_p также записываются как defaults производного запуска. В остальных движках они входят в request plan. Статус применения к server defaults отделён от требования настройки клиента; сохранение профиля не выдаётся за выполненный запрос.

## Метрики и ограничения

На экран не перенесены демонстрационные числа из визуального референса. Скорость доступна только из сопоставимого сохранённого бенчмарка: тот же исходный профиль, близкий вход 4K, совпадающие launch/sampler параметры. Иначе «Не измерено». Это исторический snapshot, не обещание текущей скорости после смены бинарника на месте. Отдельного автоматического fingerprint бинарника в этом модуле нет.

Контекст исходного профиля — предел конфигурации, а не автоматическое доказательство recall на всей длине. Существующий lastKnownGood используется только как один из признаков приоритета. Изображения и автономные инструменты не включаются по одному имени пресета: модуль не добавляет tool definitions, vision projector или права на выполнение действий. Совместимость конкретного внешнего клиента проверяется отдельно.

## Основные файлы

- `app/src/features/smartTasks/` — presets, чистый planner, черновики, применение и React-компоненты.
- `app/src/styles/kontur/smart-tasks.css` — локальный слой оформления.
- `app/src/locales/{ru,en}/smartTasks.json` — переводы.
- `app/src/views/ConfigurationView.tsx` — вкладки и сохранённый технический редактор.
- `app/src/store/control.ts` — действие создания производного профиля без рестарта сервера.
- `app/src-tauri/src/strata.rs` — ограниченное создание и удаление производного JSON.
- `app/tests/smartTask{Planner,Application}.test.ts` — правила, совместимость и границы сохранения.

## Проверки

- TypeScript и production frontend build.
- `validate:static`: переводы, ссылки на ключи, соответствие frontend IPC native handlers. Отдельного ESLint/lint script в проекте нет; новая зависимость для него не добавлялась.
- `verify:modules`: границы чистых модулей.
- Vitest: правила planner, сохранение, ошибки ресурсов, rollback, router identity; существующие тесты профилей и приложения.
- Native Rust: тесты производных Strata JSON, неизменности источника, ограничений контекста и пути; остальные library tests.
- Итог: 270 frontend-тестов; 128 native-тестов, 6 интеграционных тестов пропущены по их штатным условиям.
- Штатная desktop-сборка: `npx tauri build --no-bundle` успешно создала `app/src-tauri/target/release/aplot-control-llm.exe` со встроенным frontend. Установщик не создавался. Сборка выдаёт предупреждения о размере JS-chunk, dynamic import и неиспользуемых Rust-структурах; ошибок нет.
- Browser preview на 1920×1080, 1440×900 и 1280×800: четыре range controls, отсутствие горизонтального переполнения, dark RU и light EN, закрепление/конфликт контекста, сохранение отдельного остановленного профиля, сохранение двух работающих demo-каналов, независимость черновиков CH1/CH2, технический редактор и отсутствие ошибок консоли.

Browser-проверка использовала штатный demo transport. Реальные загрузки больших LLM и перенастройка стороннего API-клиента в рамках этой реализации не запускались. Native сохранение/файловые ограничения проверены в изолированных fixtures.

Снимок browser preview и краткое подтверждение проверок находятся в `app/artifacts/smart-tasks-2026-10-14/`. System theme проверена через настоящий control настроек и смену prefers-color-scheme: dark/light меняют тему без изменения разметки модуля.
