# Модульный установщик Aplot — 19 октября 2026

## Принятый вариант

### Фирменный мастер установки и обслуживания

Обычный запуск `setup.exe` открывает новый мастер в стиле Aplot: тёмная палитра, логотип приложения, понятные шаги «Начало → Компоненты → Проверка → Выполнение → Готово». Интерфейс на русском. Под ним остаётся существующий NSIS и общий исполнитель установки компонентов; отдельный прототип не используется.

На первом экране два явных варианта: **«Экспресс-установка»** (только Aplot) и **«Выборочная установка»** (движки, агенты и дополнительные пакеты). Для новой установки предлагается `%SystemDrive%\Aplot Control LLM`; у обнаруженной установки сохраняется её прежний путь. В экспресс-режиме шаг компонентов пропускается в обе стороны. Окно имеет фиксированный размер, боковые мелкие пояснения убраны. Версии движков в карточках не выводятся; технические версии остаются в каталоге и журналах.

При выборе новой установки компонента появляется включённый флажок **«Установить дополнительные пакеты»**. Его можно отключить отдельно для каждого компонента. Для нативных движков проверяется Microsoft Visual C++ x64 Runtime; при необходимости загружается проверенный пакет с официального сервера Microsoft. Он может запросить права администратора собственным диалогом Windows; автоматической перезагрузки нет. Для Strata/Hermes устанавливаются отдельные Python-окружения и Python-пакеты, для NVIDIA-версии Strata — CUDA runtime/cuBLAS. DLL, уже включённые в официальный архив движка, сохраняются как часть этой поставки. Драйвер видеокарты установщик не заменяет.

Если дополнительные пакеты отключены, загрузки Python, uv, pip-пакетов и установка VC++ не выполняются. Для Strata/Hermes требуется готовое окружение либо совместимый установленный Python с нужными пакетами; при отсутствии зависимостей проверка останавливает подготовку с объяснением, а компонент не публикуется как готовый. Повторное использование найденного движка не меняет его внешнее окружение.

Обнаружение учитывает настройки и профили, каталог готовых компонентов, PATH, стандартный каталог Ollama и переносную структуру `engines` рядом с установщиком/приложением. Поиск ограничен папками приложения и не обходит все диски или библиотеку моделей. Источник setup передаётся нативному модулю отдельно: распаковка помощника во временную папку больше не теряет исходную переносную установку. На рабочем компьютере проверка из отдельной временной папки обнаружила все пять движков и Hermes.

Перед выполнением показаны итоговые действия и папка. Этапы и ошибки отображаются в мастере; подробный журнал можно открыть отдельно. Отмена во время установки останавливает работу после текущего компонента.

Перед установкой приложения есть два независимых флажка: **«На рабочем столе»** и **«В меню „Пуск“»**. Оба по умолчанию сняты. Выбор передаётся внутреннему NSIS через `/SHORTCUTS=none|desktop|startmenu|both`; тихая установка без этого параметра не создаёт ярлыки. Ярлык удаления в «Пуске» также зависит от выбора меню. Существующие ярлыки не удаляются при снятых флажках. В режиме управления только модулями этих настроек нет.

На экране выполнения показаны общий счётчик обработанных компонентов и процент по этому счётчику. Это доля компонентов, а не оценка оставшегося времени. Для загрузок отдельно отображаются измеренные байты, размер, скорость и процент; для распаковки — число файлов и процент. Проверка SHA-256, подготовка Python, установка пакетов и проверка запуска отображают текущий этап и прошедшее время без выдуманного процента. Бесконечная движущаяся полоска убрана. Исполнитель передаёт структурированные события `APLOT_PROGRESS` в UTF-8; обычный технический вывод остаётся в журнале.

Лицензии читаются в отдельном окне с прокруткой, крупным текстом, перечнем документов и ссылками на официальные источники. Кнопка установки доступна после стандартного флажка **«Я принимаю условия лицензионных соглашений.»**. Список включает лицензии Aplot и выбранных новых компонентов/пакетов: MIT, Apache, Python/uv, условия Microsoft и NVIDIA, а также поставляемые уведомления Infernix/Ollama и LLVM OpenMP. Уже используемая внешняя установка повторного принятия не требует. Тексты включены в `installer/licenses.json`, источники и скрипт обновления — `scripts/refresh-installer-licenses.py`; сборка не скачивает лицензии из интернета. Исходные тексты LICENSE/NOTICE внутри поставок сохраняются.

Мастер проверяет регистрацию Aplot в Windows для текущего пользователя и всех пользователей, включая обе разрядности реестра, а также приложение в выбранной папке:

- Найдена старая версия — предлагается **обновление** в её папке.
- Найдена та же версия — предлагается **восстановление** файлов приложения.
- Найдена более новая версия — установка старой версии поверх неё блокируется.
- **Управлять компонентами** позволяет добавлять и удалять модули без переустановки оболочки.

Обновление сохраняет настройки, проекты, модели и профили. Приложение нужно предварительно закрыть, включая значок в трее. Автоматическое обновление установки для всех пользователей этим пользовательским установщиком не выполняется: мастер объясняет ограничение. Отдельную переносную копию можно выбрать через папку и зарегистрировать установкой в неё. Установщик содержит конкретную версию приложения; поиск более новой версии Aplot в интернете не выполняется.

`uninstall.exe` открывает тот же фирменный мастер с выбором удаления приложения или управления компонентами. Движки, Hermes, кэш и общий Python выбираются отдельно и по умолчанию сохраняются. Общий Python нельзя удалить, пока остаются зависящие от него собственные Strata/Hermes. Перед удалением доступны точные пути. Отдельный флажок удаления данных относится к каталогам Aplot в профиле Windows; внешние проекты, модели и данные переносной копии им не удаляются.

Мастер собран на WPF/.NET Framework 4.8 средствами Windows; он не требует WebView для собственного интерфейса. NSIS продолжает обеспечивать установку приложения, WebView, регистрацию и ярлыки. Для исходного мастера с русским/английским языком предусмотрен `/CLASSIC`; тихие `/S`, пассивные `/P` и служебные `/UPDATE` сохраняют прежнее поведение. Справка платформ: [Microsoft .NET Framework в Windows](https://learn.microsoft.com/en-us/dotnet/framework/install/on-windows-10), [установщики Windows в Tauri](https://v2.tauri.app/distribute/windows-installer/).

Компактный онлайн-установщик NSIS: оболочка входит в EXE, дополнительные компоненты скачиваются только по выбору пользователя. Встраивать все движки и Python-окружения в установщик не нужно: один только Windows-архив Ollama занимает около 1,4 ГиБ. Веса LLM и Whisper не включены и автоматически на этапе установки не загружаются.

- **Экспресс** — приложение Aplot. Дополнительные движки и агенты не устанавливаются; существующие пути и профили продолжают работать.
- **Выборочная** — независимые галочки llama.cpp, Strata, Ollama, QwFNfer, Infernix, Hermes CLI. По умолчанию галочки сняты.
- **Использовать найденные компоненты** включено по умолчанию. Обнаружение учитывает текущие настройки и профили, выбранную переносную папку Aplot, опубликованный каталог компонентов, PATH и стандартные каталоги. Неизвестный нестандартный каталог вне этих источников нужно подключить через настройки приложения.
- Снятие флажка повторного использования устанавливает выбранные версии в отдельные каталоги. Существующие файлы и профили не перезаписываются. Указанные пользователем пути движков не заменяются; новые пути подставляются в пустые настройки. Для Hermes применяется выбранное установщиком расположение CLI.
- Модули можно добавить позже повторным запуском установщика. Невыбранные установленные модули при этом не удаляются.

## Каталог компонентов

Версии проверены по официальным GitHub-источникам 19 октября 2026. В каждом установщике фиксируется конкретная редакция и SHA-256, без плавающего скачивания `latest` во время установки.

| Компонент | Версия | Поставка |
|---|---|---|
| llama.cpp | b11723 | Официальный Windows x64 CPU/Vulkan архив ggml-org/llama.cpp |
| Strata | 0.1.45 | Исходники фиксированного коммита и Windows CUDA 13 / HIP архив Niko1221/Strata; backend по GPU |
| Ollama | 0.40.6 | CLI/runtime Windows x64; приложение Ollama Desktop и автозапуск не устанавливаются |
| QwFNfer | 0.3.0 | Готовая Windows CUDA сборка основного Apolog1ze-Dev/QwFNfer; отдельная сборка форка не нужна |
| Infernix | windows-2026.10.18 | Готовый официальный Windows x64 архив; нужна NVIDIA RTX 50 |
| Hermes CLI | 0.22.2 | Исходники фиксированного коммита, locked Python-окружение с voice extra; без Hermes Desktop |

Источники, хеши, размеры архивов и типы установки: `app/src-tauri/installer/components.json`. Python и uv устанавливаются только при выборе Strata/Hermes. Strata использует Python 3.12, текущий locked Hermes — 3.14. Системный Python и PATH не изменяются. У Strata сохраняется проверенный API-патч Aplot из `integrations/strata/aplot-api.patch`; он применяется только к новой собственной копии.

Официальная QwFNfer 0.3.0 не равна форку QwFNfer-Secure-Multilang: нет его API-ключа, prefix cache, async I/O и переопределения MTP GPU, а KV поддерживается f16/q8_0. Для установленной через каталог официальной сборки Aplot отклоняет такие настройки до запуска с объяснением. Базовый локальный запуск доступен; существующая установка форка и её профили сохраняются и повторно используются. Полная проверка инференса с весами моделей в тест установщика не входит.

Это каталог установщика, а не автоматическое обновление существующих движков на рабочем компьютере. При подготовке следующего выпуска обновляются ссылки/версии/хеши каталога и подписи выбора, затем повторяются проверки установки и интеграции. Не обновлять каталог слепо только по номеру тега: у llama.cpp `/releases/latest` может содержать только указатель nightly; у новых Hermes меняются требования к Python.

## Хранение и ошибки

Компоненты размещаются в `%LOCALAPPDATA%/Aplot Control LLM/components/<id>/<version>`. Сверенные архивы и Python-кэш остаются рядом для повторного использования. `installations.json` публикует только готовые расположения. Пользовательские модели и профили туда не копируются. При удалении оболочки компоненты сохраняются по умолчанию; теперь их можно отдельно отметить в мастере удаления.

## Удаление приложения и модулей

`uninstall.exe` создаётся **после установки через setup.exe** в выбранной папке приложения. Запуск отдельного `aplot-control-llm.exe` не создаёт деинсталлятор и запись в списке установленных приложений Windows.

В установленной версии есть три входа: **Настройки → Компоненты и удаление → Удалить Aplot**, ярлык **«Удалить Aplot Control LLM»** в меню «Пуск» (если его создание выбрано при установке) и список приложений Windows. Настройки проверяют именно папку запущенной копии. Если рядом нет `uninstall.exe`, интерфейс объясняет ситуацию и предлагает открыть приложения Windows; для переносного EXE удаление выполняется из его папки после закрытия.

Для удаления только модулей, без удаления оболочки:

1. Открыть **Настройки → Компоненты и удаление**.
2. Отметить нужные движки/агента. Показаны версии, объём файлов и раскрываемые пути с кнопкой проводника.
3. При необходимости отдельно отметить скачанные архивы/кэш. Общие Python/uv доступны для удаления только вместе со всеми установленными через Aplot Strata и Hermes либо после их удаления.
4. Нажать **«Удалить выбранные»** и проверить список в подтверждении.

Удаляются все принадлежащие установщику версии выбранного модуля, включая незавершённую установку с его маркером. **Все файлы внутри этих папок, в том числе добавленные вручную, удаляются вместе с модулем.** Модели за пределами папок компонентов, проекты, история и профили остаются. После успешного удаления в настройках очищаются пути, указывавшие внутрь полностью удалённых модулей. Профили не удаляются: для их повторного запуска потребуется переустановить модуль или выбрать другой путь.

Внешние движки, подключённые из собственных папок, показаны в режиме просмотра: Aplot не удаляет чужую установку по одному сохранённому пути. Неопознанные каталоги без маркера установщика тоже не удаляются. Работающий процесс, чужая блокировка установки, повреждённый манифест или ссылка наружу останавливают удаление до соответствующей операции. Внутренние junction-псевдонимы Python, созданные uv, удаляются как ссылки без обхода их содержимого. При ошибке заблокированного файла маркер модуля сохраняется для повторной попытки; независимые модули могут быть удалены успешно. Результат — `last-removal.json` в папке компонентов.

Мастер деинсталляции предлагает отдельные флажки тех же модулей, кэша и Python. По умолчанию они сняты. При обновлении приложения модули никогда не удаляются. Тихое удаление без `/REMOVE_COMPONENTS=` сохраняет их; явный пример: `uninstall.exe /S /REMOVE_COMPONENTS=llama_cpp,hermes,cache`. Удаление настроек и истории по-прежнему управляется отдельной галочкой мастера. Ошибка удаления модуля прерывает удаление оболочки и показывает расположение отчёта.

Проверки этой доработки: 358 frontend-тестов, 150 Rust-тестов (7 внешних проверок пропущены), проверка исходников/переводов, release-сборка NSIS. Среди восьми новых Rust-проверок — выборочность, сохранение чужих файлов, зависимости Python, занятый процесс, блокировка установщика, junction наружу и внутренний псевдоним uv, повтор после заблокированного файла. `app/tests/component-maintenance-cli.ps1` проверяет собранный EXE на отдельных фикстурах: INI-инвентаризацию, реальное удаление выбранного тестового модуля/кэша, сохранение соседнего проекта, манифест и зависимость Python. Он включён в Windows CI и release-проверки. В изолированной GUI-копии проверены данные настроек, выбор и отмена подтверждения; в NSIS-предпросмотре — экран модулей, русские подписи и финальная кнопка. Удаление рабочих установок через GUI не выполнялось.

Загрузка идёт по HTTPS из разрешённых официальных репозиториев; до распаковки проверяется SHA-256. Проверяется выход ZIP-путей за каталог назначения. Окружение Python создаётся по окончательному пути, чтобы editable-установка Hermes не ломалась из-за переноса. Существующие каталоги без маркера установщика не заменяются.

Если модуль не удалось загрузить/подготовить, оболочка остаётся установленной, независимые выбранные модули обрабатываются дальше. Установщик сообщает о частичной ошибке и возвращает ненулевой код. Подробности: `install.log` и `last-result.json` в каталоге компонентов. Повторный запуск использует проверенный кэш и продолжает подготовку собственного незавершённого каталога. Состояние «готов» записывается только после проверки нужного EXE и Python-импортов; модель и сервер при этом не запускаются.

## Сборка и сопровождение

- `npm run tauri:build` собирает NSIS с `tauri.release.conf.json`.
- Шаблон NSIS взят из официального Tauri и расширен диспетчеризацией фирменного интерфейса и модульными страницами; источник и MIT-лицензия сохранены рядом.
- `Install-Components.ps1` — общий исполнитель; `components.nsh` — диспетчеризация фирменного мастера, классические страницы и вызов исполнителя.
- `installer/ui/Installer.xaml` и `Installer.cs` — фирменный интерфейс. `npm run installer:ui` компилирует его и запускает 26 проверок политик и ресурсов. Release-сборка выполняет этот шаг автоматически.
- `--component-maintenance-state <report.json> [папка Aplot]` — чтение состава модулей, версий, размеров и принадлежащих установщику путей без запуска GUI или миграций.
- `--component-inventory <report.json> [папка Aplot]` — нативное чтение только путей компонентов до запуска Tauri, без запуска интерфейса, миграций или вывода API-ключей.
- Дополнительный последний аргумент `--component-inventory <report.json> <папка Aplot> <исходная папка setup>` сохраняет источник поиска при запуске из TEMP. В PowerShell-исполнителе используются `-DiscoveryRoot` и `-SkipDependencies`.
- Тихая установка без `/COMPONENTS=` не скачивает дополнительные модули. Для автоматизированной установки можно передать `/COMPONENTS=llama_cpp,hermes`; идентификаторы проверяются по каталогу. Диагностика и ненулевой код при ошибке сохраняются.

## Проверка

Для фирменного мастера дополнительно проверены политики обновления/восстановления/понижения версии, установка для всех пользователей, кодирование Windows-аргументов, зависимости Python и встроенный каталог. `app/tests/installer-ui-acceptance.ps1` компилирует отдельный файловый NSIS-стенд без регистрации в Windows: реальное обновление и повторное восстановление проходят по пути с кириллицей и пробелами, SHA-256 нового EXE совпадает, контрольные настройки, модель и проект сохраняются. Проверки включены в Windows CI и release-скрипт.

В GUI проверены запуск фирменного мастера из собранного setup, обнаружение существующей версии, карточки компонентов, выбор и итоговый экран. Удаление просмотрено в режиме предпросмотра, который блокирует выполнение. Полная установка/деинсталляция рабочей копии пользователя для этой проверки не выполнялась.

В отдельной папке `app/artifacts/components-acceptance` реально загружены, сверены и подготовлены все шесть компонентов. Проверка EXE выполнена через справку/usage без модели. Для Strata проверены зависимости, CUDA DLL, применение API-патча и импорт Python-сервера. Для нового Hermes прошли 3 интеграционные проверки с локальным тестовым API: файлы, вложения, разрешения, продолжение сессии, контекст и ручная диктовка без открытия микрофона. Повторный выбор всех шести использовал существующие файлы без повторного скачивания.

Дополнительно проходят PowerShell-проверки экспресс-режима, отбора компонентов, повторного использования, сохранения версии, отказа при неверном SHA-256/ZIP traversal и изоляции ошибок, 2 Python-теста применения патча и 142 Rust-теста (7 внешних проверок пропущены). Отдельная сборка «Aplot Installer Acceptance» прошла тихую экспресс-установку в `app/artifacts/installer-shell-check`: установлены только EXE, legal и installer-ресурсы, движки не добавлялись. В мастере проверены русский язык, оба режима и все шесть независимых флажков. Проверка удаления тестовой копии не выполнялась: автоматическая проверка разрешений отклонила деинсталляцию и последующую адресную очистку. Тестовая копия оставлена отдельно и может быть удалена пользователем через список установленных приложений. Пользовательские установки движков и Hermes в ходе проверки не обновлялись.


## Исправления после проверки на другом компьютере

Загрузка архивов выполняется с тремя попытками и докачкой `.partial` через HTTP Range. При отказе сервера от докачки файл загружается заново; итоговый SHA-256 обязателен перед распаковкой. Уже подготовленные Python и пакеты остаются для повторной попытки. После ошибки загрузки Strata не считается установленной только из-за наличия Python: незавершённый маркер без маркера готовности исключает компонент из обнаружения и повторного использования. Ошибки PowerShell и Python передаются в UTF-8, причина неудачи показывается рядом с компонентом на итоговом экране.

Выбор движка для запуска и фильтры библиотеки используют реальное обнаружение файлов. При отсутствии llama.cpp его проверка на старте не запускается. Если установлен только Strata, приложение выбирает Strata; если готовых движков нет, предлагает установку или указание пути в настройках. Пустые пути заполняются найденными установками, явно заданные пути сохраняются. Автозапуск другого движка при такой смене не выполняется. В настройках и начальной настройке остальные движки доступны для ручного подключения с отметкой «Не установлен».

Текущие проверки: 363 frontend-теста, 153 Rust-теста (7 внешних проверок пропущены), 26 политик и ресурсов WPF, проверки компонентов PowerShell, NSIS-стенд четырёх сочетаний ярлыков и восстановления, реальный HTTP-стенд обрыва/докачки/отказа от Range/двух неудачных попыток. Системные компоненты на компьютере пользователя в этих проверках не устанавливались. Полную установку на том другом компьютере необходимо повторить новой сборкой; его исходный текст ошибки был повреждён кодировкой и точную первопричину по нему подтвердить нельзя.


## Пустая библиотека Strata

Установка движка без скачанных моделей — штатное состояние: `discover_strata_models` возвращает пустой список, если в исправной установке ещё нет `strata-*.json`. Библиотека показывает обычное предложение добавить модели без красного сообщения и требования запускать `START-HERE.bat`. Ошибки чтения папки, отсутствующего Python и повреждённых существующих конфигураций сохраняются. Регрессии проверены на стороне Rust и хранилища интерфейса: 365 frontend-тестов и 155 Rust-тестов прошли, 7 внешних Rust-проверок пропущены.
