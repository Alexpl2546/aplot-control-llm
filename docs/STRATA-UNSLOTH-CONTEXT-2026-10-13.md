# Strata Unsloth: заполненные контексты 65К, 98К и 131К

Все шесть комбинаций прошли: в каждой 80/80 точных значений, 40/40 carryover и 80/80 checkpoint. У обеих моделей в этом тесте одинаковая точность, а UD-IQ4_XS быстрее читает контекст и почти вдвое быстрее генерирует ответ. Для продолжения опытов с длинными текстами на данном ПК практичнее UD-IQ4_XS; преимуществ UD-Q4_K_XL в точном извлечении этот набор не показал. Все тестовые серверы остановлены, исходные конфигурации сохранились побайтно.

Измерения на локальном ПК 13 октября 2026. RTX 5080 (16 303 МиБ VRAM), 64 ГБ RAM, Windows 11; Strata 0.1.43.1. Две квантизации одной Qwen3.8-Flash-Next: Unsloth UD-IQ4_XS и UD-Q4_K_XL. Каждый из шести запусков изолирован, последователен, на localhost:18087; пользовательские конфигурации не менялись.

Общие параметры: KV q4_0, KV resident 32 768 токенов, RAM-бюджет экспертов 32 ГиБ, VRAM reserve 1536 МиБ, prefill auto, MTP spec 4 / min-p 0.5. Остальные параметры взяты из установленных конфигураций. Стандартный STRATA_ROUTE_TAIL_SKIP=7 активен; это результат штатного режима Strata с пропуском части экспертов при decode, а не полностью точного вычисления всех весов.

## Методика и результаты

Штатные Rust-наборы Aplot `context-recall-v1` и `context-stability-v1`, версия 2, по одному прогону. Первый набор — одно окно; второй — три окна с последовательными checkpoint. В каждом окне один recall-запрос проверяет 20 точных случайных десятисимвольных значений, равномерно распределённых по тексту; второй запрос создаёт checkpoint. Всего 24 окна и 48 запросов генерации за 52,5 минуты работы тестовых серверов. Промпты подогнаны точным API-счётчиком; лимит контекста минус 1900 токенов оставлен для ответа/сжатия. Генерация greedy, seed 42, thinking отключён. Набор сам генерирует и сохраняет случайные seeds данных; данные разных прогонов не идентичны. Порог прохождения каждого окна: ≥95% для текущих значений, carryover и checkpoint. Никаких повторов ради улучшения результата.

Первый токен и скорость генерации — среднее по четырём recall-запросам с новым полным ledger. Сжатие повторно использует prefix cache и в эти средние не входит. Суммарная проверка каждого успешного запуска: 80 текущих значений, 40 переносимых значений и 80 значений в checkpoint. Исходные results.json содержат подробные метрики каждого запроса, точные ответы и ожидаемые значения, seeds, заполнение контекста и статусы окон.

Пики памяти из resources.csv измерены каждые 5 секунд: VRAM всей видеокарты и RAM всей системы, включая другие приложения. Это наблюдаемые пики выборки, не гарантированные максимумы и не объём исключительно весов модели. В results.json аппаратные метрики снимаются до/после запроса, поэтому для пиков в таблице использован независимый монитор.

Один прогон на комбинацию даёт практическую проверку работы на данном ПК, но не статистическую оценку превосходства одной квантизации. Ledger-аудит проверяет точное извлечение и перенос данных; качество кода, рассуждений и произвольных документов он не оценивает.

В начале запусков Strata предупреждала о небольшом запасе Windows commit: 3,9–4,1 ГиБ при лимите 66,8 ГиБ. Поэтому автоматическая CPU-доля prefill не включалась. Файл подкачки и системные настройки не изменялись. Успешные результаты относятся к наблюдавшейся нагрузке и этим настройкам; физическая свободная RAM и запас commit — разные показатели.

## Артефакты

`app/artifacts/strata-unsloth-context-2026-10-13/`: campaign.json, summary.json, run.py, report.py и отдельная папка для каждой модели/контекста. В ней config.json, server.log, engine.log, benchmark.log, results.json, изолированная SQLite база результатов, resources.csv, run.json. Временные API-ключи являются публичными одноразовыми строками для localhost.

Использован существующий исполняемый Rust test harness llama_control_lib-60e36259252650f9.exe (SHA-256 зафиксирован в run.json). В нём исторически жёстко задано имя Infernix в profileName/configSnapshot. Это только подпись исходных результатов: реальный сервер — Strata, что подтверждают команда, временная конфигурация, /v1/models и engine.log. Производственная база профилей в этих тестах не используется.
