# Проверка моделей и профилей — 14 октября 2026

Оборудование: RTX 5080, 16 ГиБ VRAM; Ryzen 7 9800X3D; 64 ГиБ RAM. Strata обновлена до 0.1.44.1. Настройки сохранены в локальной базе Aplot и конфигурациях Strata. Исходные веса ранее установленных моделей сохранены.

## Методика и границы результатов

Движки запускались последовательно. Скорость — медиана трёх запросов со свежим входом около 4096 токенов; использованы реальные timings движка. Во время измерений и проверки длинного контекста загрузки приостанавливались. TTFT измерялся клиентом до первого видимого токена; это время обработки свежего промпта, без выигрыша от повторного кеша. Размер вывода по умолчанию 128 токенов; для reasoning/совместимости llama.cpp использовался увеличенный лимит. Разные архитектуры и режимы рассуждения не являются строго равноценными по полезности токенов.

Таблица сравнивает выбранные рабочие профили. Для прежних IQ3/IQ4/Q4 сохранён штатный route tail skip=7 (движок пропускает часть слабых экспертов); у NVFP4 штатно выключен tail skip, в тесте явно задан 0. Поэтому различие скоростей между квантами не является чистым измерением стоимости квантования. Для IQ3 отдельный tail skip=0 дал 51,0 вместо 72,1 ток/с при тех же 11/12 коротких задачах; точность на любых задачах этим не доказана.

Колонка JSON — 12 небольших синтетических задач: арифметика, преобразование списков, сортировка, агрегация, пропуски, Unicode, соблюдение формата, защита от инструкции внутри данных и дата. Проверяется точное совпадение извлечённого JSON с ожидаемым объектом. Колонка «строго» дополнительно требует, чтобы весь ответ являлся этим JSON без Markdown и постороннего текста. Это оценка выполнения конкретных инструкций, а не общая оценка интеллекта, программирования или качества ответов. Режим теста: temperature=0, top_p=1, top_k=0, min_p=0, seed=42, reasoning отключён где поддерживается.

Проверка контекста использует точный счётчик API и непрозрачные случайные коды в заполненном окне, не менее 99% целевого размера после резерва около 1900 токенов на вывод. В двух окнах проверяются 40 текущих кодов, 20 кодов переноса и 40 элементов checkpoint. В одном окне 128K проверяются 20 текущих кодов и 20 элементов checkpoint. Один успешный seed не доказывает устойчивость на любых текстах.

Перед сохранением новых Strata/Infernix параметров потребован измеренный запас не менее 8 ГиБ свободной физической RAM, 4 ГиБ свободного Windows commit и 1536 МиБ VRAM. Монитор снимал показатели раз в 3 секунды; межвыборочные пики могут быть выше. Поэтому скорость менее безопасных вариантов не переносилась в рабочие профили.

## Новые модели

- Qwen3.6-35B-A3B-MTP, UD-Q4_K_XL: [репозиторий Unsloth](https://huggingface.co/unsloth/Qwen3.6-35B-A3B-MTP-GGUF), ревизия `5bc3e238d916f48a861bac2f8a1990a0e9b7e98d`. Вес 22 853 663 008 байт (21,28 ГиБ); SHA-256 `55983c5a75a1ab969824077b3bb3de4146e82a9234072b48ad4e8f92ad3fe9f1`. Конфигурация `engines/strata/strata-qwen36-ud-q4_k_xl.json`; профиль **Qwen3.6 35B UD-Q4_K_XL · 32K · Strata**. Выбраны `--expert-vram 6`, `--mtp 2`, контекст 32768. Эта архитектура использует KV f32. MTP2: 76,4 против 61,3 ток/с при одинаковом размещении (+24,6%). Более агрессивные 8 ГиБ экспертов показывали 86,1 ток/с, но оставляли лишь около 0,5 ГиБ VRAM и отклонены. Вариант 64K с expert-vram 4,5 прошёл короткий набор (72,3 ток/с), но полный 64K не подтверждён и не выбран.
- Flash Next NVFP4 GPTQ: [репозиторий готового пакета Strata](https://huggingface.co/Maximilian228/Qwen3.8-Flash-Next-NVFP4-GPTQ-Strata), ревизия `640a1db97446ddd5e89d2b70ecd0297987192c93`. Полный комплект около 119,17 ГиБ включает experts.bin, dense.bin, dense/PLE GGUF, embeddings и токенизатор. Все файлы проверяются по SHA-256 из закреплённой ревизии; отдельные хеши и пути находятся в `download-nvfp4-complete.json`.

NVFP4: выбран `new-nvfp4-budget24`; конфигурация `strata-nvfp4-nvfp4.json`, контекст 131072. Среда: `{"STRATA_ROUTE_TAIL_SKIP": "0"}`. Параметры: `--max-context 131072 --kv q4_0 --resident-budget-gib 24 --vram-reserve-mib 2560 --kv-resident 32768`. MTP и контроль tail skip взяты из проверенной конфигурации; изменение tail skip для ускорения не использовалось.

Стандартный NVFP4 prefill использует W4A8 (int8 tensor path). Само наличие весов NVFP4 не означает, что FP4 x FP4 MMA включён. В этой установленной сборке `STRATA_PREFILL_NVFP4=w4a4x2` из одного раздела документации отвергается при запуске: бинарник и `src/prefill/moe_mmq.cu` принимают `w4a8`, `w4a4` и `fp16`. Доступный `w4a4` проверен отдельно; по разделу «Prompt path precision» в `engines/strata/docs/NVFP4.md` он сильнее меняет численную точность. Сохранён W4A8, чтобы не менять её ради одного короткого набора задач. Режим W4A4 относится к обработке промпта; скорость decode не должна интерпретироваться как ускорение от FP4 tensor cores.

## Изменения остальных профилей

- Три Strata Flash Next (IQ3_S, UD-IQ4_XS, UD-Q4_K_XL): RAM экспертов 24 ГиБ, VRAM reserve 2048 МиБ, KV resident 32768 при max-context 131072, MTP/spec 4. Для двух Unsloth включён `STRATA_HC_Q8=1`. При одинаковом бюджете памяти HC_Q8 дал 50,5 → 56,9 ток/с (+12,7%) для IQ4 и 27,1 → 31,7 (+17,0%) для Q4. Это не прирост всего нового профиля относительно старого: уменьшение бюджета с 32 до 24 ГиБ снижает IQ4 с 63,8 до 56,9, а Q4 с 32,5 до 31,7 ради запаса памяти. Исходный IQ3 без ограничения RAM не смог безопасно загрузиться. MTP2 оказался медленнее MTP4 и не выбран. Кванты сохранены.
- Infernix Flash Next Uncensored 128K: MTP2, KV int8, RAM экспертов 24576 МиБ, RAM headroom 12288 МиБ, VRAM headroom 3072 МиБ, prefill chunk 4096, host context 2048 МиБ, concurrency 1. При одинаковых безопасных параметрах MTP2 дал 36,56 → 45,70 ток/с (+25,0%), результат JSON остался 11/12. Обновлены профиль и глобальные настройки Infernix. Исходный автоматический бюджет показал более высокую скорость, но на заполненном 128K оставлял менее 1 ГиБ commit и около 0,5 ГиБ VRAM; он отклонён.
- GPT-OSS 20B / llama.cpp: parallel 2 → 1. Общий пул 65536 прежде давал 32768 на слот; теперь `/slots` подтверждает 65536 на один запрос. Остальные настройки сохранены. В коротком наборе есть ошибки родного Harmony/PEG формата; форсирование reasoning budget 0 не исправило их. Полный 64K не проверялся.
- RVN Qwen27 / llama.cpp: MTP отключён (`--spec-type none`) после воспроизводимого CUDA illegal memory access. Перевод draft cache в f16 устранял падение, но ответы оставались некорректными. Вместе с MTP отключены prompt cache и context checkpoints: `--no-cache-prompt --cache-ram 0 --ctx-checkpoints 0`, repeatPenalty=1.0. После этого 12/12 задач, строгий JSON 12/12, около 35,65 ток/с. Без отключения кеша MTP-off давал лишь 4–5/12. Существующее имя **RVN Qwen27 · 64K · MTP** сохранено ради стабильного идентификатора маршрута; описание профиля прямо указывает отключённый MTP. Полный 64K не проверялся.
- Ornith 9B / llama.cpp: те же параметры отключения prompt cache/checkpoints и repeatPenalty=1.0. Устранены невидимые/повторяющиеся ответы при temperature=0; 9/12, строго 7/12, около 80 ток/с. Отдельный sampled-вариант дал 10/12, но изменение sampler не выбрано как замена исправлению кеша. Prompt cache теперь не ускоряет повторный префикс диалога. Полный 64K не проверялся. [Карточка модели](https://huggingface.co/ornith-ai/Ornith-1.5-9B) описывает её reasoning/template особенности.
- Bonsai, Gemma 12B, Gemma E4B, QwFNfer и обе модели Ollama: параметры сохранены после коротких замеров. Для Gemma 12B 10/12 извлечённых ответов при лишь 1/12 строго JSON — формат ответа требует внимания в сценариях машинного разбора. Qwen2.5 0.5B быстрая, но 3/12 в этом наборе; не выбрана вместо более крупных моделей для строгих задач.
