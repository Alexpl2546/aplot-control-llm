# Agent Workspace: целевой уровень и состояние возможностей

Дата: 18 октября 2026 года.

## Принцип продукта

Aplot развивается в полноценную рабочую среду для локальных моделей и агентов. Русский интерфейс, аккуратное оформление и удобство настройки дополняют функциональность агента. Упрощение экрана не должно ограничивать доступ к инструментам, разрешениям, контексту и диагностике.

Сопоставимость с привычными агентными приложениями оцениваем по законченным рабочим сценариям: задача → инструменты → проверяемый результат → просмотр изменений → продолжение работы. Наличие красивого чата само по себе не означает функциональный паритет.

## Что реализовано

| Возможность | Текущее состояние |
| --- | --- |
| Локальные серверы | Сохранены существующие интеграции llama.cpp, Strata, Ollama, QwFNfer и Infernix; API работает независимо от рабочей среды |
| Главная | Быстрый запуск модели, вход в диалог или работу с агентом, недавние задачи, проекты и требующие внимания процессы |
| Управление серверами | Контекстное меню, запуск/остановка/перезапуск через существующие механизмы, быстрое окно выбора готового профиля; компактные S1/S2 |
| Рабочая среда | Обычный диалог и агентные задачи в одном разделе |
| Hermes | Настоящий установленный Hermes через stdio JSON-RPC; чтение/изменение файлов, терминал, навыки, память, todo, уточнения и разрешения |
| Задачи и проекты | Папки проектов, отдельные задачи, закрепление модели к задаче, архив, сохранение истории, память проекта, список активных сессий в основной панели |
| Работа в фоне | Владение запросами находится вне компонентов страниц; переходы между разделами не отменяют выполнение |
| Вложения | Выбор файлов и изображений, вставка изображений из буфера и перетаскивание в поле ввода; до 8 вложений по 25 МиБ |
| Голос | Локальное распознавание Whisper base через Hermes в редактируемый черновик; отправка вручную |
| Контекст | Занятие окна именно текущей сессии, источник измерения, приблизительная разбивка и файлы контекста |
| Разрешения | Один раз, на сессию и всегда — когда Hermes предлагает соответствующую область; видимый выбор режима доступа |
| События | Текущее состояние процессов и структурированная история; отдельный технический журнал для stdout/stderr |
| Производительность | Мониторинг, карта памяти, существующая настраиваемая раскладка, бенчмарки и история измерений в одном разделе |
| Темы и язык | Существующие токены «Контура», RU/EN, светлая и тёмная темы |

## Что нельзя считать уже готовым

| Направление | Реальное ограничение | Следующий законченный сценарий |
| --- | --- | --- |
| Другие агенты | Подключён только Hermes. Codex, Claude и другие исполнения не добавлены | Единый контракт адаптера: запуск, события, инструменты, разрешения, контекст, продолжение сессии; затем конкретные адаптеры |
| Продолжение после перезапуска | Сохраняется история интерфейса. Новая сессия получает редактируемую сводку; это не полное восстановление внутреннего состояния Hermes | Настоящее возобновление по ID сессии, подтверждение доступности модели и каталога, восстановление tool/todo-контекста |
| MCP и браузер | В частном окружении Aplot они пока не включены. Настройки и секреты Hermes Desktop автоматически не импортируются | Экран подключения инструментов, проверка соединения, область доступа к проекту, отображение реальных вызовов |
| Терминал | Команды выполняются и результаты видны как события инструментов; полноценного интерактивного терминала пока нет | Просмотр stdout в процессе, запуск/остановка, понятные cwd и оболочка, интерактивные сессии |
| Редактор и Git | Есть просмотр файлов, результатов и записанных изменений; полноценный редактор и панель Git не добавлены | Просмотр diff, выборочное применение/отклонение, ручная правка, статус Git и проверка результата |
| Управление постоянными правилами | Выбор «Всегда» сохраняет правило Hermes для задачи. Отдельного редактора/отзыва правил пока нет | Видимый список правил, область действия, удаление и синхронизация с действующей сессией |
| Ограниченный доступ | «Без терминала» исключает терминал; чтение и изменение файлов остаются доступны | Отдельно реализовать и проверить read-only режим или настоящее изолированное исполнение; не выдавать текущий режим за sandbox |
| Долговременные задания | Активные worker-процессы живут в текущем запуске приложения; закрытие приложения завершает их | Устойчивое возобновление, очередь заданий, восстановление после сбоя и уведомления |
| Качество модели | Передача изображений и инструментов не гарантирует, что конкретная локальная модель хорошо их использует | Воспроизводимые проверки tool calling, vision, работы с файлами и выполнения задач; рекомендации на основании измерений |
| Речь | Реализована ручная диктовка до остановки/отправки/отмены, таймер и уровень микрофона; локальный Whisper base на CPU. Полноценный разговор с прерыванием и озвучиванием не добавлен | Отдельно спроектировать голосовой диалог и выбор локальных STT/TTS |

## Порядок развития

1. Надёжность текущего рабочего цикла: вложения, разрешения, контекст, события, сохранность истории и диагностика.
2. Полное продолжение сессий, просмотр/редактирование результатов, diff и Git, терминал в процессе выполнения.
3. Настройка MCP и браузерных инструментов, управление правилами доступа.
4. Контракт нескольких агентных исполнений и реальные интеграции других агентов.
5. Очередь и долговременное выполнение, более полный голосовой режим.

Каждый пункт считается завершённым после проверки настоящего сценария с реальным исполнением. Не добавляем неработающие кнопки, фиктивные статусы или обещания возможностей, которые ещё не подключены.
