## Выбор контекстов и методика

В 39 сохранённых профилях: 65 536 — 13, 98 304 — 12, 131 072 — 10, 262 144 — 3, 131 000 — 1. Выбраны четыре стандартных наиболее частых размера; недавние отметки использования профилей подтверждают эти размеры. Источник: обезличенный `app/artifacts/infernix/context-selection.json`. Это частоты профилей, а не статистика всех запросов.

На каждом размере запускается отдельный сервер Flash Next: KV int8, spec off, concurrency 1, prefill chunk 1024, host context 4096 МиБ, RAM headroom 4096 МиБ, VRAM headroom 1536 МиБ, expert RAM auto. Подсчёт токенов использует настоящий tokenizer и chat template движка, `enable_thinking=false` одинаково для count и generation. Дополнительно проверены совпадение count/usage, публичный model alias и HTTP 401 без ключа.

Один прогон recall и один прогон continuity с тремя окнами. В каждом длинном промпте 20 случайных значений распределены по всему контексту; после ответа выполняется compaction/checkpoint. Во втором и третьем окне continuity проверяется перенос 20 значений из предыдущего checkpoint. Порог прохождения — 95% для каждого критерия и завершение всех окон. Используется синтетический корпус; сообщения пользователя не читались. Seeds и ожидаемые/полученные значения сохранены в JSON. Это проверка корректности одного прогона, а не оценка статистической надёжности. HTTP-таймаут Aplot — 900 секунд на запрос; timeout означает отсутствие результата в этот срок, а не доказанную ошибку извлечения значений.

Ниже TTFT и скорости относятся к первому длинному recall без сохранённого префикса. Короткая compaction с повторным использованием prefix cache не смешивается с ними. GPU CSV опрашивается каждые 5 секунд; пик VRAM включает остальные процессы Windows. RAM в JSON — снимки занятой памяти всей системы, не измерение пикового RSS сервера. Во время ранних прогонов параллельно выполнялись загрузки моделей и сборка Aplot.

На 262 144 оба длинных запроса отклонены HTTP 503 внутри SSE: планировщик сообщает нехватку main_kv (3555/3554 страниц сверх ресурсов простаивающего движка). Объявленная ёмкость сервера не гарантировала возможность принять полный промпт. В Aplot исправлена обработка таких SSE-ошибок: они сохраняются как ошибка запроса, без измеренных скоростей; точность при отказе запроса не оценивается. Предыдущий прогон `flash-next-reserve-full` содержал неверные скорости для пустых ответов и исключён из итогов. Добавлены регрессионные проверки HTTP 200 с ошибкой SSE после частичного ответа, включая последний event без перевода строки.

Подробности: `app/artifacts/infernix/results/flash-next/ctx-<размер>-int8/`: `run.json`, `results.json`, `server.log`, `benchmark.log`, `gpu.csv` и отдельная SQLite. `status=completed` в run.json означает завершение тестового процесса; качество определяется `suiteSummary.passed` и результатами окон.

## Dense 27B: запуск на 16 ГБ VRAM

Проверки запуска выполняются отдельно после освобождения GPU от Flash Next. Все три варианта не прошли запуск с контекстом 65 536, KV int8 и резервом VRAM 1536 МиБ: после загрузки весов доступно 0 байт для автоматического KV headroom (требуется 1 610 612 736 байт). Логи движка показывают веса 18,1 ГиБ для NVIDIA, 16,4 ГиБ для Quasar и 19,0 ГиБ для Uncensored. Поэтому тесты генерации и качества на этой RTX 5080 для этих моделей выполнить невозможно. Большие контексты не запускались после отказа самого небольшого выбранного размера.

- nvidia-27b: `failed`, engine exited during startup: 1; see server.log. Лог: `app/artifacts/infernix/results/nvidia-27b/ctx-65536-int8/server.log`.

## Практические ограничения

Flash Next использует offload экспертов в RAM/SSD. На первом запуске 65K в RAM размещено около 34,5 ГиБ экспертов (12 969 из 24 576), остальные читаются с SSD. Поэтому задержка первого ответа на заполненном контексте существенно больше задержки compaction с prefix cache. Размер контекста меняет распределение VRAM между KV и кэшем экспертов.

В мониторинге Aplot скорости рассчитаны из приращений Prometheus-счётчиков; upstream публикует часть prefill-счётчиков блоками, поэтому мгновенный график может иметь всплески. TTFT мониторинга — среднее с запуска; TTFT теста — конкретный запрос. Физический KV с сохранёнными префиксами не выдаётся за длину активного промпта.

Prefix cache используется в RAM. Сохранение на диск не выставлено в интерфейсе: upstream сохраняет его при двойном Ctrl+C, управляемый скрытый процесс Aplot останавливается средствами ОС.

Настройки Flash Next подготовлены с проверенным контекстом 65 536. Перед их записью сохранена `data/backups/infernix-before-settings-2026-10-09.sqlite3`. Выбранный ранее движок, профили и история пользователя сохранены; результаты этой кампании находятся в отдельной тестовой базе.
