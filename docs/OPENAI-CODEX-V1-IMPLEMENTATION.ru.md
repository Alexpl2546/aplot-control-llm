# ChatGPT и Codex в Aplot — первая реализация

19 октября 2026 года. Это описание внесённых изменений; прежняя техническая проработка остаётся проектным документом.

## Как начать

1. Обновить Aplot новым установщиком. В выборочной установке можно выбрать **Codex CLI** как отдельный агент. Уже установленный native Codex обнаруживается автоматически; его путь можно также указать вручную.
2. Открыть **Чат → Подключения OpenAI**. Это же окно доступно из блока лимитов внизу бокового меню.
3. Для обычного чата нажать **Continue with ChatGPT** и завершить авторизацию в системном браузере. Затем выбрать ChatGPT и модель в верхней части чата. Локальный сервер для этого не нужен.
4. Для агента отдельно нажать **Войти в Codex через ChatGPT**. В **Агентной среде → Новая задача** выбрать Codex и его модель. Открытая папка проекта задаёт рабочую папку агента.
5. Режимы доступа находятся в поле ввода. Если Windows требует первоначальной подготовки песочницы, в подключениях есть **Настроить песочницу Windows**; система может запросить права администратора. Ошибка песочницы не переключает агента на полный доступ.

На первом запуске есть **Подключить ChatGPT или Codex**: мастер больше не требует настраивать локальный движок для облачной работы.

## Что добавлено

- Самостоятельная авторизация ChatGPT для прямого подписочного Responses-транспорта обычного чата: PKCE, state/nonce, проверка подписи ID token по опубликованным JWKS, issuer/audience/expiry, выданный client ID, проверка предоставленных scopes, refresh и отзыв при выходе. Запросы отправляются только в публичный официальный API.
- Данные этой регистрации зашифрованы Windows DPAPI. UI получает состояние подключения, имя аккаунта и каталог моделей, без access/refresh token. Секреты не входят в экспорт проекта или профилей.
- Отдельный native Codex app-server по stdio. Он использует собственный Aplot `CODEX_HOME`, принудительный вход ChatGPT и Windows credential store (`keyring`); ошибка хранилища не переводит секреты в открытый файл. Внешние Desktop/CLI сессии пользователя не копируются и не удаляются.
- Codex работает в существующей агентной области рядом с Hermes. Его сообщения, команды, поток вывода команд, изменения файлов/diff, вопросы, разрешения, остановка и usage преобразуются в общие события Aplot. Файлы и изображения можно прикладывать к задаче.
- В sidebar указан фактический агент активной задачи. Блок лимитов Codex показывает остаток, длительность окон, сброс и последнее обновление; поддерживает несколько квот, недоступность и устаревшие данные. Это квота аккаунта, а не контекст текущего чата.
- Каталог моделей получается отдельно для обычного ChatGPT-чата и Codex. Отображение модели в каталоге не выдаётся за доказательство подписочного доступа.
- Codex — отдельный необязательный модуль установки и удаления. Закреплён официальный Windows-релиз 0.163.0, SHA-256 архива проверяется, вспомогательные executables и notices сохраняются. Веса моделей, Hermes и Python при выборе только Codex не устанавливаются.

## Поведение первой версии

Обычный облачный чат и Codex имеют **два явных входа**. Обычный чат использует регистрацию Aplot через Sign in with ChatGPT, Codex — управляемую самим Codex авторизацию. Это позволяет получать его штатные account limits, не смешивая scopes разных способов входа. В обоих случаях пользователь завершает согласие в браузере. Доступ зависит от разрешений и плана выбранного аккаунта.

Чат принимает текст и поддерживает потоковую выдачу и остановку. Уход со страницы не уничтожает выполняющийся запрос. В обычном чате нет локальных команд и инструментов агента. При исчерпании подписки автоматического перехода на платный API нет.

Задача закрепляет выбранного агента и модель. Для их смены после начала истории создаётся новая задача. История агентной области сохраняется прежним механизмом Workspace; после перезапуска приложения первая версия использует существующий сценарий **новой сессии с явной передачей выбранного контекста**, а не обещает автоматическое восстановление выполнявшейся команды.

Перевод скрытых внутренних рассуждений не реализуется. Показываются только пояснения и summaries, которые отдаёт Codex. Контекст берётся из usage runtime; отсутствующая ёмкость не заменяется фиксированным 64K/128K.

Для диктовки Codex отдельный распознаватель пока не подключён: кнопка явно недоступна с пояснением. Диктовка Hermes сохраняется. Навыки и AGENTS.md Codex применяет своим штатным механизмом; интерфейс установки навыков Hermes не становится автоматически менеджером навыков Codex.

## Проверка

- TypeScript и проверки границ/статических переводов.
- Тесты Responses SSE: UTF-8 и CRLF по одному байту, оборванный ответ, ошибка после текста, обязательное подтверждённое завершение.
- Тесты Codex adapter: режимы доступа, решения разрешений, постоянное правило только при наличии execpolicy amendment, вопросы, ошибки команд, контекст и гонки остановки/завершения turn.
- Тесты квот: used → remaining, отсутствие второго окна, объединение одновременных чтений, сохранение старого snapshot с пометкой ошибки.
- Rust-тесты, включая scopes/expiry/nonce и допустимые RPC. Модульные проверки установщика и его 26 проверок политики.
- Реальный обмен со стабильным Codex 0.163.0 в отдельной пустой папке: initialize, account/read, model/list и ожидаемый отказ account/rateLimits/read без входа. Запросов inference — 0. Отчёт: `app/artifacts/openai-codex-analysis/stable-probe.json`.
- Через Computer Use проверены отдельное окно Aplot, облачный путь первого запуска, окно подключений, состояние лимитов без входа и наличие Codex в выборе агента. Авторизация и песочница через UI не запускались. Использована отдельная тестовая БД; старые Hermes истории при первом запуске теста были прочитаны механизмом миграции, исходные истории не изменялись. После этого механизм изоляции распространён и на путь миграции.

Реальная авторизация конкретного аккаунта, получение его лимитов и полный ответ модели под подпиской **не проверены без участия пользователя**. Успешная сборка и локальные тесты не подменяют эту проверку.
