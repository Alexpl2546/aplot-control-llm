# Team Room: единые подключения и развитие Aplot

Дата анализа: 19 октября 2026. Репозиторий: https://github.com/iintuziasty-web/team-room
Зафиксированный commit: `206f9d350695e11bdcb0ece4bff6e38b608c98ad`, package version 1.1.0.

Это исходный анализ и предложение по реализации. После него выполнен первый этап внедрения: фактический состав изменений и ограничения описаны в [отчёте о реализации](UNIFIED-CONNECTIONS-2026-10-19.ru.md). Дальнейшие рекомендации ниже не означают, что все они уже реализованы.

## Главный вывод

В Aplot нужен один раздел **«Подписки и подключения»** и одно подключение аккаунта каждого провайдера, используемое обеими областями приложения: «Чат» и «Агентная среда». Установка CLI и авторизация аккаунта должны быть разными состояниями интерфейса.

У OpenAI и Anthropic разные механизмы авторизации. Общий пользовательский интерфейс не означает обмен токенами между провайдерами или универсальный API для всех подписок.

Team Room подтверждает полезность подхода «собственная оболочка над официальными CLI». Однако в этом репозитории нет отдельного прямого доступа к ChatGPT через SiWC: Codex и Claude работают через свои CLI. Это отличается от уже реализованного прямого чата Aplot.

## Единое подключение OpenAI

Официальная документация прямо описывает использование собственного SiWC-токена приложения в Codex app-server без второго входа:
https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server

Предлагаемый сценарий:

1. В «Подписках и подключениях» пользователь один раз выбирает «Подключить ChatGPT».
2. Прямой чат использует это подключение через Responses API.
3. Codex получает тот же действующий токен только через окружение принадлежащего Aplot дочернего процесса, с официальной конфигурацией Responses provider.
4. Обновление токена координирует один native-компонент Aplot. Токен не попадает в React, аргументы команд, историю или журнал.
5. При смене токена app-server перезапускается и возобновляет сохранённый thread. Активный запрос не отправляется повторно автоматически: это могло бы повторить действия инструментов.
6. Выход отключает оба потребителя и завершает только процессы/сессии, принадлежащие этому подключению Aplot.

Получение лимитов через `account/rateLimits/read` при этом типе provider требует отдельной проверки. Если CLI не отдаёт окна, показываем «Лимиты недоступны для этого подключения». Не заставляем проходить второй вход ради процентов и не используем недокументированные адреса ChatGPT.

Каталог `model/list` может быть встроенным, а не перечнем прав аккаунта. В интерфейсе различаем «есть в каталоге», «доступ подтверждён ответом» и «проверка не выполнена».

## Единое подключение Claude

Для нашей оболочки следует использовать **неизменённый официальный Claude Code** с его собственным штатным входом. Aplot обнаруживает CLI, предлагает установить его отдельным модулем и запускает авторизацию самого CLI. Проверка состояния выполняется через `claude auth status`; секретные файлы не читаются и не копируются в Aplot.

Существуют важные различия между способами использования:

- Встраивание неизменённого Claude Code с личным входом пользователя описано в официальной документации.
- Собственная реализация входа claude.ai в Aplot и посредничество с токенами подписки ограничены документацией Anthropic. Не переносим OpenAI OAuth-код на Claude механически.
- Для чата с подпиской предлагаем запуск того же Claude Code в режиме без инструментов; для агентной среды — его полноценную сессию с разрешениями пользователя.
- Прямой Claude API остаётся отдельным подключением и отдельным способом оплаты. Не включаем его незаметно, если подписка недоступна.

Источники и различия формулировок проверены 19 октября:

- https://code.claude.com/docs/en/legal-and-compliance — отдельно описаны размещение оригинального CLI и ограничения на посредничество с OAuth.
- https://code.claude.com/docs/en/cli-reference — команды входа/статуса/выхода, JSON-поток, продолжение сессии, ограничения инструментов.
- https://code.claude.com/docs/en/headless — программное управление официальным CLI.
- https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan — актуальные сведения об использовании плана и API credits. Их нельзя считать разрешением на самостоятельное хранение подписочных токенов сторонним приложением.

Для режима «Чат» недостаточно написать в промпте «не используй инструменты»: отключаем встроенные инструменты и MCP средствами CLI, а также исключаем выполнение пользовательских hooks и расширений в этом режиме. Поддержку конкретных флагов проверяем на выбранной версии CLI. Новый чат и агентная задача имеют разные native sessions, даже если используют один аккаунт.

Ограничения подписки показываем по реально полученным данным CLI. Отсутствие снимка означает «Пока нет данных», а не 100% остатка. Счётчик контекста не подменяет лимит подписки. Подписка сама по себе не добавляет API распознавания голоса: существующая диктовка Aplot остаётся самостоятельной возможностью.

## Как будет выглядеть управление

В общих настройках добавляем «Подписки и подключения». В нём карточки:

- **OpenAI / ChatGPT**: аккаунт, состояние, использование в чате и Codex, доступность CLI, лимиты, обновление состояния, выход.
- **Anthropic / Claude**: аккаунт официального Claude Code, состояние CLI, использование в чате и агентной среде, известные ограничения и выход.
- **API и локальные подключения**: самостоятельные источники моделей, отличимые от подписок.

В чате выбираются подключение и модель. В агентной среде — исполнитель, совместимое подключение, модель и режим разрешений. Повторные кнопки входа в этих двух областях заменяются ссылкой на один раздел подключений.

Состояния «CLI установлен», «аккаунт подключён», «модель доступна», «лимиты известны» отображаются независимо. Подключённый OpenAI без установленного Codex позволяет работать в прямом чате и предлагает добавить CLI только для агента.

## Что внедрять из Team Room

| Приоритет | Возможность | Польза для Aplot | Как встроить |
|---|---|---|---|
| 1 | Общие подключения + Claude Code | Один вход для обоих режимов, три исполнителя в общей среде | Расширить текущие native-адаптеры и Zustand; сохранить Hermes и локальные серверы |
| 2 | Возобновление native sessions и передача задачи | Продолжить работу тем же агентом или передать другому без ручного пересказа | Сохранённые ID сессий, аккаунт, папка, проверка принадлежности; явная передача с предпросмотром контекста |
| 3 | Очередь уточнений | Можно дополнить задачу, пока агент работает | Состояния «в очереди», «получено», «применено», «доставка не подтверждена»; поддержка возможностей каждого адаптера |
| 4 | Доска активных задач | Понятно, кто работает, кто ждёт разрешения и где уже есть результат | Дополнительный вид существующих задач, без второй независимой базы задач |
| 5 | Карточки субагентов | Видно дочернюю работу и её результат | События native runtime, отдельная лента, остановка только при поддержке API |
| 6 | Просмотр изменений и результатов | Быстрая проверка файлов, diff и HTML-превью | Расширить существующий сервис артефактов и действия файлов проекта |
| 7 | Два диалога рядом | Сравнить решения, поручить проверку другому агенту | Две панели React на общем хранилище; каждому диалогу своё подключение и состояние |
| 8 | Подключение других компьютеров и телефона | Запустить работу на домашнем ПК и следить удалённо | Отдельный будущий модуль устройства/хаба, а не обязательный сервер для настольного Aplot |

Первый полезный сценарий передачи: Hermes подготовил файлы → пользователь выбирает «Передать Codex» → видит сводку, выбранные файлы и ограничения → Codex продолжает в новой собственной сессии. Переносим историю и результаты; внутренние состояния двух агентов не объявляем идентичными. Передача и создание сводки могут расходовать контекст и лимиты.

## Изменения в архитектуре Aplot

Сохраняем Tauri/Rust + React/Zustand. Не переносим Node-хаб и отдельный веб-интерфейс Team Room внутрь приложения.

Общие сущности:

- `ConnectionProfile`: ID подключения, провайдер, отображаемое имя аккаунта, источник авторизации, состояние и возможности. Секретов в UI нет.
- `AgentRuntime`: Hermes, Codex, Claude; установлен ли runtime, поддерживает ли продолжение, уточнения, approvals, изображения, навыки и телеметрию.
- `TaskRoute`: исполнитель, подключение, модель, effort, разрешения и рабочая папка.
- `NativeSessionRef`: исполнитель, подключение/проверенная идентичность, native session ID и рабочая папка.
- `UsageSnapshot`: источник, момент получения, окна лимитов, отдельный контекст сессии и признаки устаревания.

В существующей реализации Codex поле `hermesSessionId` используется и для Codex thread ID. Перед третьим исполнителем стоит ввести общее поле native session с миграцией, сохранив совместимость со старыми задачами. Маршруты должны привязываться к конкретному подключению, чтобы смена аккаунта не продолжила чужую сессию.

Точки расширения: `src-tauri/src/openai_connection.rs`, `codex_agent.rs`, новый Claude-адаптер, `src/services/agent.ts`, `src/services/codex.ts`, `features/agent/workspaceModel.ts`, общий store подключений и существующий `AgentChat.tsx`. Каталог установщика дополняется независимым модулем Claude с официальными условиями поставщика.

## Что не переносить буквально

1. **macOS-специфичное управление процессами.** В `lib/run-processes.mjs` Windows-ветка возвращает пустой stop. Для Aplot нужны принадлежащие runtime процессы и Windows Job Objects/другой проверенный способ управления деревом; нельзя завершать все процессы `claude.exe` или `codex.exe` на машине.
2. **Файловое хранение авторизации Codex как универсальное решение.** Team Room явно задаёт file store для дополнительных аккаунтов. Это не эквивалент защищённого хранилища Windows. Сохраняем native-защиту Aplot и официальный механизм Claude.
3. **Фиксированные окна контекста.** В репозитории есть общий бюджет 350 000 и переопределение Codex context window на 400 000 для списка моделей. У Aplot берём реальные значения runtime/модели, а неизвестные оставляем неизвестными.
4. **Дополнение каталога статическим списком как доказательство доступа.** `lib/claude-models.mjs` сам помечает такие модели непроверенными. Каталог и фактическое право использования — разные состояния.
5. **Автоматическое переключение аккаунта/провайдера без понятного правила пользователя.** Это меняет обработчика данных, контекст и расход подписок. Начинаем с явной передачи; автопереключение — только отдельный настраиваемый сценарий.
6. **Предположение об одинаковых разрешениях.** Native auto-review, ограниченный доступ и полный доступ имеют разные гарантии у CLI. Показываем реально поддерживаемые режимы и не подменяем sandbox инструкцией в промпте.
7. **Смешивание окончания ответа и завершения всей работы.** Team Room специально ждёт состояние idle и учитывает дочерние задачи. Это полезный принцип, но требует проверок на каждом runtime.

Team Room распространяется под MIT. Если заимствуем исходный код, сохраняем copyright и текст лицензии в THIRD_PARTY_NOTICES/поставке. Лицензия Team Room не заменяет условия официальных Claude/Codex и их зависимостей.

## Критерии приёмки первой очереди

- Один вход OpenAI становится доступен прямому чату и Codex; отдельный Codex login не требуется.
- Один штатный вход Claude Code становится доступен чату через CLI и Claude в агентной среде.
- Отсутствие CLI не выглядит как ошибка аккаунта; отсутствие данных лимитов не выглядит как исчерпанная квота.
- Выход и смена аккаунта не продолжают задачу с другой идентичностью и не затрагивают сторонние приложения.
- Обновление токена не повторяет запросы/действия инструментов и не теряет сохранённую переписку.
- Чат Claude не имеет исполняемых инструментов, hooks или MCP; полноценный режим агента уважает выбранные разрешения.
- Переключение страницы не прекращает генерацию; остановка действует на соответствующую сессию.
- Есть проверки ошибок сети, недоступной модели, отказа доступа, потерянного процесса, отмены и восстановления.
- До заявления о готовности выполняются реальные ручные входы и короткие запросы на аккаунтах пользователя; текущий анализ этого не проверял.

Рекомендуемый порядок: завершить общий слой подключений OpenAI → добавить неизменённый Claude Code с общим аккаунтом для двух режимов → укрепить возобновление/передачу задач → очередь уточнений и доска → субагенты и два диалога → удалённые компьютеры.
