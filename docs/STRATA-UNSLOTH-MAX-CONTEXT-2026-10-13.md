# Unsloth: поиск рабочего предела контекста

Тесты на локальном ПК: Strata 0.1.43.1, RTX 5080 (16303 МиБ VRAM), 64 ГБ RAM, Windows 11. Рабочие профили и конфигурации на 131072 не менялись. Все тестовые конфигурации сохранены отдельно в папках результатов.

## Результаты

Прогоны Unsloth IQ4 остановлены 14 октября по просьбе пользователя из-за времени обработки. Затем проверен IQ3_S на Strata 0.1.43.1. Обычный профиль IQ3_S на 131072 остановился по защите памяти. Полные замеры выполнены в отдельных копиях конфигурации с ограничениями памяти; рабочие профили пользователя не менялись.

IQ3_S успешно обработал 131072, 393216 и 524288 токенов. На 131072 и 393216 выполнено по одному окну с recall и checkpoint 20/20. На 524288 дополнительно выполнены три последовательных окна в одном запуске: recall 60/60, перенос checkpoint 40/40, checkpoint 60/60. Ошибок, остановок сервера и OOM не было; минимальный наблюдаемый запас составил 19.50 ГиБ RAM, 5.02 ГиБ Windows commit и 1.83 ГиБ свободной VRAM. Наибольший стабильный контекст в проверенном диапазоне — 524288. Выше него тест не запускался.

- IQ3_S: максимальный размер, прошедший минимум три окна с достаточным запасом памяти, — 524288.
- UD-IQ4_XS: максимальный размер, прошедший минимум три окна с достаточным запасом памяти, — не установлен.
- UD-Q4_K_XL: максимальный размер, прошедший минимум три окна с достаточным запасом памяти, — не установлен.

Это максимумы проверенного диапазона, а не математический предел модели или гарантия для всех задач. В штатном диапазоне метаданные GGUF задают 262144 токена. ## Что считается успешным

В каждом полном окне проверяются 20 точных десятисимвольных значений, распределённых по тексту. В следующих окнах также проверяются 20 значений из предыдущего checkpoint. После ответа отдельный запрос сжимает результат в checkpoint. Порог — ≥95% в каждом окне для recall, carryover и checkpoint. Не допускаются ошибки HTTP, timeout, nonfinite или остановка по нехватке памяти. В Python-прогонах дополнительно требуется естественное завершение обоих ответов (`stop`), а не обрезание по лимиту вывода.

Для вывода «Подтверждён: 3 окна» требуются три последовательных окна в одном запуске, успешные recall/carryover/checkpoint во всех окнах и запас не менее 8 ГиБ RAM, 4 ГиБ Windows commit и 1,5 ГиБ VRAM. «Повторно подтверждён» дополнительно требует двух отдельных прогонов по три окна. Это выбранный запас для этого ПК; значения CUDA free могут отличаться от nvidia-smi из-за памяти драйвера.

Размер входа измерен точным API `/v1/chat/completions/input_tokens`, а не оценён по символам. Цель — лимит контекста минус 1900 токенов; фактический вход должен быть не меньше 99% этой цели. Запас нужен для ответа и checkpoint. Генерация greedy, seed 42, thinking выключен, лимиты ответа 1024 / checkpoint 600 токенов. Случайные seeds данных сохранены в results.json.

Начальные прогоны в штатном диапазоне выполняет прежний Rust-набор Aplot: один recall и три окна continuity. Он использует общий timeout запроса 900 секунд. В его исходных результатах исторически указана подпись Infernix; фактический сервер — Strata, доказательства в config.json, /v1/models и engine.log.

Для быстрого поиска используется Python-порт того же ledger-протокола: одно окно. Он не является подтверждением стабильности сам по себе. Прогоны `confirm` повторяют несколько окон на новых случайных данных; число повторов/окон указано в run.json и results.json. Python использует socket timeout 3600 секунд; время первого токена более 900 секунд несовместимо с стандартным timeout текущего Rust-бенчмарка Aplot, даже если сам сервер закончил обработку. При совпадении генератора с Rust восемь предыдущих окон воспроизвели все ожидаемые коды и позиции — driver-parity.json. Полные API-входы и ответы Python-прогонов сохранены для воспроизведения.

## Память и условия

Основные прогоны начинают с параметрами рабочих профилей: KV q4_0, KV resident 32768, RAM экспертов 32 ГиБ, VRAM reserve 1536 МиБ, prefill auto, MTP 4 / min-p 0.5. В отдельных прогонах увеличивается резерв VRAM и уменьшается RAM экспертов; значения перечислены в таблице. Это другие настройки памяти, их скорости нельзя напрямую приписывать прежним профилям. Пользовательские профили не изменяются.

Метрические CSV снимаются каждые 5 секунд: VRAM всей видеокарты, RAM всей системы, RSS дерева сервера, Windows commit used/limit. Это наблюдаемые пики и минимумы выборки, не гарантированные экстремумы. Файл подкачки управляется Windows автоматически; лимит commit может расти и уменьшаться. Свободная физическая RAM и свободный commit — разные показатели. Системные настройки файла подкачки не менялись. Если свободная RAM ниже 3 ГиБ или запас commit ниже 256 МиБ в трёх последовательных измерениях, новый runner останавливает только собственный тестовый сервер и сохраняет resource-stop.json.

Время первого токена и генерация усреднены по recall-запросам с новым полным ledger. Checkpoint повторно использует prefix cache и не включён в это среднее. Измеренные скорость и точность относятся к данной нагрузке, одному GPU и фоновому потреблению памяти данного ПК.
