# Agent Workspace V2 — реализация

Дата: 18 октября 2026. Реализация внесена в исходники Aplot Control LLM по `PROMPT.ru.md` из `APLOT_AGENT_WORKSPACE_V2_HANDOFF.zip`. PNG V2 использованы как визуальная спецификация. HTML из архива не встроен в продукт.

## Что реализовано

- В существующем разделе «Чат» сохранены два режима: обычный чат и агент Hermes. Глобальная навигация, серверы, API, профили и дизайн-токены «Контура» сохранены.
- Внутри режима агента: локальная панель проектов/задач, компактная шапка, основной чат, фиксированный композер, инспектор по запросу. На узкой ширине глобальное меню переходит в существующий компактный режим, задачи — в выдвижную панель. RU/EN и Dark/Light/System используют существующую инфраструктуру.
- Проект открывается из настоящей папки. Задачи именуются, переименовываются, ищутся и архивируются; фоновые вопросы/завершения отмечаются как непрочитанные. Выбор другой задачи или раздела не владеет жизненным циклом процесса Hermes.
- Задача хранит конкретный `runId`, поколение запуска, модель, движок, контекст и имя профиля. Выбор глобального сервера не переключает работающего агента. Несовпавший запуск требует явной новой сессии.
- Существующий Hermes CLI продолжает работать через собственный stdio RPC и отдельный Aplot-owned home. Отображаются поток ответа, оригинальные свёрнутые рассуждения, реальные инструменты, параметры/вывод, длительность, ошибки, уточнения и разрешения. Кнопка «Остановить задачу» использует существующее прерывание.
- У действий различаются выполнение, успех, ошибка, отказ, прерывание и неподтверждённый исход. Само событие `tool.complete` не означает успех. Три одинаковых подтверждённых сбоя показывают предупреждение; автоматическая остановка этим предупреждением не заявляется.
- Markdown поддерживает заголовки, списки, таблицы и код с копированием. HTML не выполняется, внешние картинки не загружаются автоматически.
- Инспектор показывает реальные файлы проекта, текстовый просмотр и раскрывает файл в проводнике. В «Результаты» попадают успешные действия записи с повторной проверкой существования файла. Diff показывается только из полученного события; это запись уже выполненного изменения, без фиктивного «Применить» или отката.
- Память проекта поддерживает создание, редактирование и удаление, категории, подтверждение, дату и источник задачи/сообщения. Только подтверждённые целые записи в пределах байтового бюджета добавляются в системную инструкцию новой сессии. У уже запущенной сессии остаётся прежний снимок; интерфейс различает эти состояния.
- «Навыки» читает настоящие `SKILL.md` из выбранного каталога. Выбранная папка передаётся Hermes как `skills.external_dirs` при новой сессии. Нет декоративных переключателей несуществующих возможностей.
- Профиль в композере показывает закреплённое имя и открывает существующие параметры запуска. Пояснение явно сообщает, что параметры отдельного запроса Smart Task Profiles ещё не переносятся автоматически в Hermes.

## Хранение и миграция

Используется существующая SQLite `data/llama-control.sqlite3`, таблица `kv`, ключ `agent-workspace-v2`. Формат: `{ version: 2, revision, data }`. В `data` находятся проекты, задачи, память, снимки потоков, выбранные проект/задача и режим чата. Сохранение транзакционное с проверкой ревизии; конфликт не перезаписывает более свежую запись и отображается пользователю. Лимит снимка — 32 MiB, 1000 проектов, 5000 задач.

При первом открытии импортируются только UUID-каталоги Aplot в `%APPDATA%/app.aplot.llamacontrol/hermes-conversations`, из их `state.db`. Импорт читает активную ветку истории; исходные базы не изменяет и Hermes Desktop не сканирует. Текущие renderer-потоки V1 также принимаются без переноса владельца работающего callback.

После перезапуска восстанавливается история, черновик, связи и память. Идентификатор живого процесса, активные разрешения и статус выполнения не восстанавливаются как действующие. Продолжение требует новой сессии и показывает редактируемую передачу последних сообщений. Рассуждения в неё автоматически не включаются; инструменты из истории не переигрываются.

Автосохранение объединяет изменения в течение 500 ms. При штатном выходе native-слой останавливает собственные процессы и запрашивает финальное сохранение renderer; явный отказ сохранения оставляет приложение открытым. Без ответа renderer ожидание ограничено двумя секундами. При аварийном завершении ОС сохраняется последний завершённый снимок.

## Границы текущей версии

1. Восстановление после закрытия — просмотр истории и явная новая сессия с передачей контекста. Полное продолжение внутреннего Hermes conversation state не заявляется. Следующий шаг при необходимости — проверить стабильный RPC resume установленной версии и добавить отдельный тест восстановления DB/session.
2. Рабочая папка — стартовый каталог, не sandbox. Native-просмотр файлов ограничен выбранным проектом; инструменты Hermes сохраняют свою существующую модель доступа.
3. Произвольные файлы, созданные терминальной командой, не объявляются результатами только по тексту ответа модели. Для полного каталога результатов терминала нужен надёжный event/file-watch источник.
4. Diff берётся из событий Hermes; универсальный редактор изменений и откат не реализованы.
5. Память и каталог навыков применяются в новой сессии. Параметры request sampling из Smart Task Profiles пока доступны через существующий редактор и пояснение, без ложного статуса «применено к Hermes».
6. Размеры просмотра ограничены: текстовый файл до 200 KB, каталог до 500 записей; обнаружение навыков глубиной до трёх уровней. Бинарные файлы не интерпретируются как текст.
7. Полный end-to-end запуск всех моделей и движков заново не выполнялся: UI использует существующую общую привязку server/generation и общий Hermes транспорт; проверки регрессии движков покрываются существующими тестами.
