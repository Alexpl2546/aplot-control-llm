# Текущий дизайн Aplot Control LLM — бриф для генерации референсов

Дата: 14 октября 2026. Приложение: Aplot Control LLM 0.8.2. Актуальный стиль в рабочем исходном коде: **«Контур»**.

Документ описывает текущую оболочку, экраны и дизайн-токены. Он предназначен для модели/дизайнера, которым нужно создать референсы новых элементов, совместимых с существующим приложением. Концепция смысловых ползунков находится в [SMART-TASK-PROFILES-CONCEPT.ru.md](SMART-TASK-PROFILES-CONCEPT.ru.md).

Основание описания — нынешние React-компоненты и активные CSS-слои. Это не описание заново запущенной установленной сборки и не результат визуальной проверки всех состояний. Исторические скриншоты `app/artifacts/screenshots` от 30 сентября и материалы `_handoff_staging` описывают более ранний интерфейс; для текущих размеров и цветов ориентироваться на этот документ и `app/src/styles/kontur`.

## 1. Назначение и характер продукта

Aplot — Windows-приложение для управления локальными LLM-серверами: модели, движки, сохранённые профили, запуск/остановка, RAM/VRAM, скорость генерации, бенчмарки, журналы и API-подключения. Поддерживаются llama.cpp, Strata, Ollama, QwFNfer и Infernix.

Визуальный характер — компактная рабочая панель с хорошо читаемыми значениями. Пользователь должен быстро различать серверы и понимать, что работает, сколько памяти занято и какие настройки ещё не применены. Главный объект — выбранный серверный запуск; его идентичность сохраняется между разделами.

Стилистические ориентиры: спокойные графитовые поверхности, тонкие разделители, маленькие радиусы, небольшие линейные иконки, ясные подписи, табличные цифры. Акцент используется для главного действия, выбранного раздела и важных активных состояний. Иллюстративный фон, большие рекламные заголовки, стеклянные панели и множество декоративных градиентов не соответствуют текущему характеру.

Приложение имеет русский и английский интерфейс, тёмную и светлую темы, а также следование системной теме. Референсы должны учитывать длину русских подписей и возможность переключения языка.

## 3. Левая панель

### Бренд

Вверху маленький лаймовый квадрат с существующим знаком Aplot: стилизованный силуэт с двумя вытянутыми верхними выступами. Размер контейнера 28×28 px, внутренний SVG 20×20 px. Рядом «Aplot Control» и строка «LLM · v0.8.2». Есть кнопка закрепления/сворачивания панели.

### Основная навигация

Шесть пунктов с линейными иконками:

1. Главная.
2. Параметры запуска.
3. Модели и профили.
4. Бенчмарки.
5. Логи.
6. API и подключения.

Настройки расположены внизу панели. Профили и модели — две вкладки общей библиотеки, а не два разных обязательных пункта навигации.

Активный пункт имеет нейтральную приподнятую заливку, более плотную подпись, акцентную иконку и короткую лаймовую полоску у левого края. Hover слегка поднимает тон фона. Иконки навигации — около 17 px.

### Серверы

Ниже навигации находится список серверных запусков. Заголовок показывает число активных/общих серверов и небольшую кнопку добавления. Каждая строка содержит:

- точку состояния;
- название запуска;
- CH1, CH2 и т. д., движок и порт;
- измеренную скорость, переходное состояние или прочую краткую информацию справа.

У каждого run свой постоянный цвет. Выбранная строка имеет нейтральную заливку и цветную полосу внутри слева. При количестве запусков больше четырёх список группируется: требующие внимания, работающие, остановленные. CH — визуальный номер канала, а не количество параллельных запросов модели.

### Нижняя часть

Компактные полосы VRAM и RAM с использованным/общим объёмом, ниже GPU %, CPU % и температура GPU. Внизу — «Настройки», RU/EN и переключатель темы. В свёрнутой панели остаются иконки и короткие обозначения каналов; при наведении/фокусе она может раскрываться поверх контента.

## 4. Верхняя и нижняя панели

Верхняя панель слева показывает цветной CH, точку состояния, имя выбранного запуска, движок/состояние и кнопку адреса API с копированием. Справа — поле запуска команд «Команда, сервер, раздел…» с Ctrl K, значок внимания/уведомлений. В browser preview дополнительно показывается Demo; в обычном desktop это не обязательный элемент.

Командная палитра открывается как компактное модальное окно. Есть поиск, группы действий/серверов/разделов, клавиатурные подсказки и список результатов с выбранной строкой. Её ширина ограничена примерно 660 px.

Нижняя строка показывает число работающих серверов, GPU %, VRAM/RAM, endpoint выбранного run, язык и версию. Типографика около 11 px, значения моноширинные. Это служебная строка; она не должна становиться второй большой панелью управления.

### Состояния

| Смысл | Тёмная | Светлая |
| --- | --- | --- |
| Готов / успешно | `#C8F27C` | `#3A7A1B` |
| Предупреждение / занят | `#F2B85B` | `#8C5800` |
| Ошибка | `#FF7070` | `#C22F2A` |
| Информация / переход | `#62C9EC` | `#15739E` |

Цвет состояния сопровождается текстом и, где уместно, иконкой. Остановленный сервер — приглушённая точка; ready — зелёная; busy — янтарная; запуск/загрузка/перезапуск — голубая с лёгкой пульсацией; crashed — красная.

Для badges используются цветной текст и слабая заливка соответствующего тона. Лаймовый акцент не означает «качество измерено», если этого фактически нет.

### Цвета каналов и графиков

Каналы CH используют постоянные различимые цвета. Тёмная тема: зелёный `#9FC86A`, голубой `#5CC4E6`, фиолетовый `#A58FFF`, янтарный `#EEB25A`, розовый `#EE82A8`, бирюзовый `#4CCDB1`. Светлая тема использует более тёмные аналоги. Эти цвета отвечают за идентичность run, а не за оценку его качества.

Графики используют родственную палитру series: `#C8F27C`, `#62C9EC`, `#A993FF`, `#F2B85B`, `#F283AB`, `#4FD1B5` в тёмной теме. У каждого цвета должен сохраняться смысл между легендой и графиком.

## 7. Геометрия и общие компоненты

Радиусы: мелкие элементы 3 px, контролы 4 px, карточки 6 px, модальные окна 8 px. Pills используют 999 px только там, где это имеет смысл — например, switch или индикатор. Обычные панели плоские, с рамкой 1 px и без заметной тени. Глубокая тень применяется к модалкам и всплывающим панелям.

Кнопки нейтральные по умолчанию, лаймовые для primary. Primary-текст тёмный в тёмной теме и белый на тёмно-зелёной кнопке в светлой. Опасные действия имеют красный контур/текст либо мягкую красную заливку. Disabled opacity около 0.5; рядом нужна причина, если действие важно.

Поля тёмные на фоне карточки в тёмной теме, с тонкой усиленной границей. Hover усиливает границу; focus — акцентная граница и мягкое акцентное кольцо. Focus-visible также получает outline 2 px.

Switch около 36×20 px, бегунок 16 px. Активный фон акцентный. Сегментированные controls состоят из маленьких нейтральных кнопок в общем приглушённом контейнере; выбранный сегмент имеет поверхность карточки и более заметную подпись.

Иконки — Lucide, линейные, обычно 14–17 px. Главные действия показывают иконку и текст. Не превращать каждую подпись в самостоятельный icon-only control.

Модальное окно — поверхность карточки, радиус 8 px, заметная тень, лёгкое затемнение/blur фона. Toast компактный, с цветной иконкой. Ошибки и recovery warnings — горизонтальные блоки с мягкой семантической заливкой и рамкой.

В пустом состоянии есть короткий заголовок, объяснение и конкретное действие. Неподдерживаемое значение показывается текстом; «—» не должно автоматически означать ноль.

## 8. Главная

Заголовок в содержимом — «Обзор», пояснение «Все серверы, память и то, что требует внимания». Справа доступна настройка плиток.

Основные элементы:

- Карточка выбранного сервера: состояние, название модели, основные факты, выбор run и действия запуска/остановки/перезапуска. Раскрываемая область содержит выбор движка, модели и профиля.
- Общая карта памяти: полосы RAM/VRAM с участками разных серверов и выделением выбранного. Другие процессы обозначаются штриховкой; рядом легенда и числовые объёмы.
- Телеметрические плитки: GPU, CPU, память, генерация, обработка промпта, активные/ожидающие запросы, TTFT, контекст и слоты.
- Графики throughput, нагрузки, памяти, температуры и запросов. Есть интервалы 1/5/15/60 минут.
- Настройка набора виджетов и режим изменения компоновки с сохранением/сбросом. Содержимое может отличаться в зависимости от выбранных пользователем виджетов.

Крупное число метрики около 26 px; название маленькое и приглушённое. Единицы измерения должны быть видны: ток/с, ms/s, %, ГиБ, °C. Карточка сервера использует спокойную двухколоночную композицию; узкие окна сводят её к одной колонке.

Новый смысловой режим на «Главной» лучше представить компактной строкой активной задачи и ссылкой в параметры, сохранив главную роль мониторинга.

## 9. Параметры запуска

Верхняя строка: заголовок страницы, описание и управление текущим профилем. Для llama.cpp доступны выбор профиля, его имя, отмена изменений, сохранение, сохранение как и возврат на главную после сохранения.

В основной части слева технический редактор, справа ресурсная оценка/план и CLI preview. В llama.cpp редактор имеет шесть вкладок: модель, аппаратные параметры, контекст, сервер, sampling, дополнительные параметры. Строка параметра содержит понятное имя, возможный CLI-флаг, control, ограничения/подсказку.

Для других движков состав отличается:

- Strata: карточка выбранной конфигурации; реальный запуск опирается на `strata-*.json`, а не на полный универсальный редактор llama.cpp.
- Infernix: собственная панель настроек и ресурсный/CLI план.
- QwFNfer: собственная панель настроек и ресурсный/CLI план.
- Ollama: собственная конфигурация и ресурсный план.

Это важно для референсов: одинаковый будущий смысловой блок может располагаться над engine-specific настройками, но не должен изображать уже существующие одинаковые технические возможности всех движков.

Состояния «изменено», «сохранено» и «фактически запущено» имеют разный смысл. В дизайне нужно удержать видимую связь между черновиком и активным сервером.

## 10. Модели и профили

Общая библиотека с заголовком, поиском, вкладками «Модели» / «Профили», фильтрами движков и действиями импорта/обновления. На вкладке моделей есть избранное, фильтры Text/Vision/Tools и назначение: coding, analysis, agents, chat, creative, documents.

Карточки нейтральные, с тонкой рамкой и небольшим радиусом. В карточке модели — название, движки/возможности, характеристики, состояние и действие настройки. Спецификации — небольшие вложенные блоки с приподнятым фоном. Profile card показывает сохранённую конфигурацию и действия. Также присутствует каталог физических model artifacts, поэтому понятия «карточка модели», «файлы» и «профиль» не всегда один объект.

Метки назначений/metadata не являются доказанным локальным рейтингом. В новых референсах «Предварительно подходит» и «Проверено локально» следует визуально различать.

## 11. Бенчмарки

Экран включает выбор профиля/теста, длины промпта и генерации, число прогонов, запуск/отмену, монитор выполнения и результаты. Есть сценарии throughput и проверки качества/контекста, сравнение, а также текущий автоподбор с целью speed/quality/balanced и ограничениями.

Референс смысловых настроек может ссылаться на этот раздел как источник подтверждений, но должен отделять завершённый результат от прогресса эксперимента. У текущего поиска есть различия поддержки движков; нельзя рисовать одинаковый завершённый автоподбор для каждого backend.

## 12. Логи, API и настройки

**Логи:** моноширинные строки на основном фоне, фильтры/управление и прокручиваемая область. Серверные ошибки должны связываться с выбранным run.

**API и подключения:** endpoint и модель фактического запуска, управление копированием, проверка подключения и справка операций. API-контракт сохраняет отдельный контекст и ID модели; успешный stream-check сам по себе не подтверждает tools или vision. Здесь естественно разместить будущий экспорт параметров запроса для task-профиля.

**Настройки:** язык, тема, масштаб интерфейса, пути к движкам/моделям и engine-specific настройки. Секреты имеют собственные действия показа/копирования. Их нельзя подставлять в декоративный пример референса.

## 13. Адаптивность и взаимодействия

Текущие responsive-правила:

- До 1440 px поле команд становится уже, колонки карты памяти компактнее.
- До 1280 px оболочка использует rail 64 px; раскрытая панель появляется поверх содержимого. Вторичные сведения верхней панели/endpoint скрываются.
- До 1100 px поле команд становится иконкой/коротким control; карта памяти и server hero переходят к одной колонке.

Нативный минимум окна — 1100 px, однако zoom и browser preview меняют эффективное пространство. Референсы стоит делать для 1920×1080, 1440×900 и 1280×800. Предложенные компоновки ниже не должны требовать горизонтального скролла всей страницы.

Motion умеренный: hover около 120 мс, switch около 150 мс, переходные состояния с пульсацией. Для reduced-motion анимации отключаются. Есть skip link, focus-visible и клавиатурная командная палитра. Новые controls должны поддерживать клавиатуру и видимый focus.

## 14. Как оформлять новые смысловые ползунки

Эта часть — предложение для будущих референсов, а не описание уже существующего компонента.

- Нейтральная карточка с поверхностью `--k-surface`, радиусом 6 px и рамкой 1 px.
- Название регулятора слева; текущее смысловое значение справа. Внизу одна короткая подсказка/последствие.
- Незаполненная часть track — усиленная граница или hover-тон; заполненная — акцент. Thumb хорошо видим в обеих темах, с focus-ring при клавиатурном управлении.
- Четыре основные шкалы вертикально, с достаточным расстоянием для различения подписи, шкалы и пояснения. Существующие поля компактные, но новый главный control должен иметь удобную область захвата; например, трек 4–6 px внутри зоны взаимодействия не менее 32 px.
- Под шкалой — 2–3 смысловые подписи, а не множество мелких непонятных чисел. Точные технические значения доступны через раскрытие.
- Disabled control объясняет причину. Если значение ограничено моделью/памятью, рядом виден предел и вариант решения.
- Пресет «Кодинг · изменён» и отдельная карточка результата помогают видеть состояние без усиления всех рамок акцентом.
- Карточка результата: модель, context per request, память, основание рекомендации и способ применения. Primary action одна на текущий сценарий.
- Акцент означает выбранное/применяемое действие; предупреждение означает конфликт или необходимость действия. Экспериментальная рекомендация не должна выглядеть как зелёная гарантия качества.

Оптимальное место — вкладка «Под задачу» на странице «Параметры запуска». Рядом остаётся «Параметры движка». Добавление нового пункта глобальной навигации для четырёх ползунков необязательно.

## 16. Готовое задание модели для генерации референсов

Ниже текст можно использовать вместе с этим файлом и концепцией:

> Создай интерфейсные референсы для существующего Windows-приложения Aplot Control LLM. Сохрани описанную оболочку «Контур»: sidebar 252 px/rail 64 px, topbar 48 px, statusbar 26 px, компактные Segoe UI/моноширинные числа, графитовую тёмную тему с лаймовым акцентом и соответствующую светлую тему. Используй точные цветовые роли и небольшие радиусы из брифа.
>
> Проработай экран «Параметры запуска → Под задачу». Основной блок: пресеты, четыре смысловых ползунка — креативность, объём задачи, глубина решения, подробность ответа — и приоритет «Быстро / Баланс / Тщательно». Справа карточка результата с моделью/движком, контекстом на запрос, бюджетом ответа, памятью, основанием рекомендации и действием применения. На компактном экране результат расположен ниже. Продумай ручное закрепление модели/температуры, состояние «Пресет изменён» и технические подробности.
>
> Покажи широкий тёмный вариант, светлый вариант и состояния: рабочий сервер с изменениями, требующими перезапуска; запрос большого контекста при закреплённой неподходящей модели; недостаточно памяти; параметры подготовлены для внешнего клиента, но ещё не подтверждено их применение. Отделяй «рекомендовано», «измерено» и «применено» с помощью текста. Не обещай проверенную coding/design-победу и не используй вымышленные проценты интеллекта. Сохраняй рабочую структуру приложения и название выбранного серверного канала. Подготовь несколько вариантов размещения нового блока и поясни различия в удобстве.

## 17. Источники в проекте

Источники для проверки размеров/поведения:

- `app/src/main.tsx` — активная точка подключения стилей.
- `app/src/styles/kontur/index.css` — порядок cascade layers.
- `app/src/styles/kontur/tokens.css` — цвет, типографика, размеры, радиусы.
- `app/src/styles/kontur/{base,components,shell,screens,responsive}.css` — оформление и адаптивность.
- `app/src/App.tsx` — shell, маршруты и темы.
- `app/src/components/shell/{KSidebar,KTopbar,KStatusBar,MemoryTrack,MemoryMap}.tsx` — оболочка.
- `app/src/components/WorkspaceChrome.tsx` — командная палитра и действия.
- `app/src/views/{DashboardView,ConfigurationView,LibraryView,PerformanceView,LogsView,ApiDocsView,SettingsView}.tsx` — текущие экраны.
- `app/src/components/runtime/ServerHeader.tsx`, `DashboardCanvas.tsx` — управление сервером и плитки.
- `app/src/locales/ru/{common,kontur}.json` — русские подписи.
- `app/src-tauri/tauri.conf.json` — начальные/минимальные размеры нативного окна.

Legacy `index.css`, `polish.css`, `studio.css` продолжают импортироваться, но находятся в нижнем cascade layer. Активные верхние слои «Контур» определяют роли и переопределяют многие старые оформления. Изолированное чтение старого `studio.css` или handoff не даёт актуальную картину интерфейса.
