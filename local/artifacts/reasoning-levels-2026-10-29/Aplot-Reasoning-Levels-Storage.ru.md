# Уровни размышлений по моделям: хранение и жизненный цикл

Дата: 2026-10-29. Статус: внедрено в 0.10.4 (`app/src-tauri/src/reasoning.rs`, `app/src/features/reasoning/profiles.ts`).

## Задача

Меню «Размышления» в чате и агентной среде должно показывать уровни **той модели, которая выбрана**, а не общий список поставщика. «Авто» подписывается уровнем модели по умолчанию: «Авто (среднее)». Уровень, которого у модели нет, не отправляется.

Сейчас список жёстко задан в `app/src/features/reasoning/reasoning.tsx` (`LEVELS`), а сервер дополнительно фильтрует его (`openai_connection.rs`: только `low…xhigh`; `claude_agent.rs`: `low…max`; `chat.rs`: `none/low/medium/high`).

## Откуда берутся данные

| Поставщик | Источник | Когда обновляется |
|---|---|---|
| Локальные модели (llama.cpp, Strata) | шаблон чата внутри GGUF: `tokenizer.chat_template` | при загрузке модели, при сканировании библиотеки (только новые или изменённые файлы) |
| Codex / ChatGPT | ответ `model/list`: `supportedReasoningEfforts`, `defaultReasoningEffort` (то же, что в `~/.codex/models_cache.json`: у GPT-6.1-Sol `low…ultra`, у GPT-6-Luna `low…max`) | при каждом подключении аккаунта и раз в сутки |
| Claude | каталог `reasoning-levels.json`: встроенная копия + свежая из репозитория | при запуске, раз в сутки |

Пользователь может переопределить список для модели вручную — переопределение важнее всех источников и не стирается пересканированием.

## Что хранится

### Таблица `model_reasoning` (новая, в `llama-control.sqlite3`)

Отдельно от `model_artifacts`: тот индекс полностью пересобирается при каждом сканировании (`artifact_service::store_catalog` удаляет всё и пишет заново), а шаблон читать каждый раз незачем.

```sql
CREATE TABLE IF NOT EXISTS model_reasoning (
  model_key    TEXT PRIMARY KEY,   -- см. ниже
  provider     TEXT NOT NULL,      -- 'local' | 'codex' | 'claude'
  path         TEXT,               -- для local: путь к первому файлу модели
  fingerprint  TEXT,              -- для local: file_identity + размер + время изменения
  source       TEXT NOT NULL,      -- 'template' | 'model-list' | 'catalog' | 'user'
  profile_json TEXT NOT NULL,      -- описание уровней, см. ниже
  detected_at  TEXT NOT NULL,
  user_json    TEXT,               -- ручное переопределение; NULL, если его нет
  missing_since TEXT               -- файл модели пропал, а ручное переопределение есть
);
CREATE INDEX IF NOT EXISTS model_reasoning_path ON model_reasoning(path);
```

`model_key`:
- локальная модель — `local:` + нормализованный путь к первому файлу (для шардов — `-00001-of-…`), в нижнем регистре, без `\\?\`;
- Codex — `codex:<connectionId>:<slug>` (у разных аккаунтов списки могут различаться);
- Claude — `claude:<connectionId>:<model id>` (как у Codex: у каждого подключения свой список).

Миграция: обычная `CREATE TABLE IF NOT EXISTS` при открытии базы (`reasoning::init_schema`), без переноса данных — таблица заполняется при первом сканировании.

### `profile_json` — описание уровней

```json
{
  "control": "effort",
  "levels": [
    { "id": "low", "label": null, "hint": "Fast responses with lighter reasoning" },
    { "id": "medium" },
    { "id": "high" }
  ],
  "default": "medium",
  "canDisable": false,
  "wire": "reasoning_effort"
}
```

- `control` — `effort` (уровни), `toggle` (только вкл/выкл), `none` (размышлений нет; меню скрыто).
- `levels[].id` — значение, которое уходит модели как есть (`low`, `max`, `ultra`, …). `label` — своё название модели, если оно есть; иначе берётся перевод `reasoning.level.<id>`, а для неизвестного id — сам id с заглавной буквы.
- `default` — уровень по умолчанию для подписи «Авто (…)»; `null`, если неизвестен.
- `canDisable` — есть ли «Без размышлений».
- `wire` — как передавать: `reasoning_effort` (+ `chat_template_kwargs`), `enable_thinking`, `codex-effort`, `claude-effort`.

Схема общая для всех поставщиков, поэтому меню и сервер работают с одним форматом.

### Каталог для Claude: `reasoning-levels.json`

```json
{
  "version": 3,
  "updated": "2026-10-29",
  "models": [
    { "match": "claude-opus-5-5", "provider": "claude", "control": "effort",
      "levels": ["low", "medium", "high", "xhigh", "max"], "default": "high" }
  ]
}
```

- Встроенная копия: `app/src-tauri/resources/reasoning-levels.json` (как `benchmark-suites.json`).
- Свежая копия: скачивается из ветки `main` репозитория, проверяется по схеме; хранится в `kv` под ключом `reasoning-catalog` вместе с `version`. Берётся та, у которой `version` больше; сбой загрузки — остаётся последняя сохранённая.
- Строки каталога пишутся в `model_reasoning` с `source = 'catalog'` при каждом обновлении каталога.

## Как определяется профиль локальной модели

Читается при разборе GGUF (`gguf.rs`): ключ `tokenizer.chat_template` сейчас пропускается; его нужно прочитать, **сразу превратить в короткое описание и не сохранять сам шаблон** (он бывает десятки килобайт и в `metadata` модели не нужен).

Правила, по порядку:
1. В шаблоне есть `reasoning_effort` — `control: effort`. Уровни — строковые литералы, с которыми он сравнивается (`'low'`, `'medium'`, `'high'`…); по умолчанию — значение из `default(...)` или `is not defined … set reasoning_effort = '…'`. Пример: gpt-oss — `low/medium/high`, по умолчанию `medium`.
2. Есть только `enable_thinking` — `control: toggle`, `canDisable: true`, по умолчанию — включено, если шаблон открывает `<think>` без условия.
3. Есть `<think>` без переключателей — `control: toggle` без отключения (модель всегда думает): меню показывает только «Авто».
4. Ничего из этого — `control: none`, меню скрыто.

Strata: модель — тот же GGUF, правило то же. Если сервер Strata при запуске сообщает поддерживаемые значения, они уточняют профиль (`source` остаётся `template`, но `levels` берутся из ответа).

## Жизненный цикл

### Загрузка модели завершена

`downloads/install.rs`, после перемещения файлов в `final_path` и записи `model_installations`:
1. для первого файла модели прочитать GGUF и построить профиль;
2. `INSERT OR REPLACE` в `model_reasoning` с `source = 'template'`, `fingerprint` текущего файла;
3. отправить событие обновления библиотеки — меню в чате подхватит без перезапуска.

Пакет Vision (`aplot-vision-*`) и прочие спутники профиля не создают: у mmproj нет шаблона чата.

### Сканирование библиотеки (`model_catalog` / `rescanModels`)

После сборки каталога, в той же транзакции, что `store_catalog`:
1. для каждой основной модели посчитать `fingerprint`;
2. строки нет — прочитать шаблон и добавить;
3. строка есть, `fingerprint` совпадает — ничего не делать (шаблон не перечитывается);
4. `fingerprint` другой (файл заменили, перекачали) — прочитать заново и обновить, `user_json` сохранить;
5. строки `provider = 'local'`, чьих путей больше нет в каталоге, — удалить, **кроме тех, у которых есть `user_json`**: их пометить отсутствующими (`path` остаётся) и удалить через 30 дней, чтобы ручная настройка пережила временно отключённый диск.

Модель переместили в другую папку: по `file_identity` (тот же файл на диске) строка переносится на новый путь вместо удаления и повторного разбора.

### Удаление модели (`model_removal::remove_model`)

После удаления файлов, вместе с очисткой `model_installations`:
- `DELETE FROM model_reasoning WHERE provider = 'local' AND path IN (<удалённые основные файлы>)` — включая `user_json`: пользователь сам удалил модель.

### Codex

При подключении аккаунта и раз в сутки, после `model/list`:
1. для каждой модели записать строку `codex:<connectionId>:<slug>` с `source = 'model-list'`;
2. модели, которых в ответе больше нет, удалить для этого `connectionId`;
3. при отключении аккаунта — удалить все его строки.

### Claude

При обновлении каталога: перезаписать строки `source = 'catalog'`; строки моделей, исчезнувших из каталога, удалить (если нет `user_json`).

### Ручное переопределение

В карточке модели («Модели и профили») — «Уровни размышлений: определены по шаблону · Изменить». Сохранение пишет `user_json`; «Сбросить» обнуляет его.

## Как используется

1. `reasoning_profile(model_key)` — команда Tauri: `user_json`, иначе `profile_json`, иначе запасной список поставщика (сегодняшний `LEVELS`).
2. Меню строится из профиля. Выбранный уровень хранится по-прежнему на поставщика; если у текущей модели его нет — показывается и отправляется «Авто».
3. Сервер проверяет уровень по тому же профилю вместо жёстких списков в `openai_connection.rs`, `claude_agent.rs` и `chat.rs` — иначе `max` и `ultra` у Codex будут отброшены.

## Проверки

- `gguf`: разбор шаблонов gpt-oss (уровни + default), Qwen3 (`enable_thinking`), шаблона без размышлений; длинный шаблон не попадает в `metadata`.
- `model_reasoning`: добавление при загрузке; повторное сканирование не перечитывает неизменённый файл; замена файла обновляет профиль и сохраняет `user_json`; удаление модели удаляет строку; переезд папки переносит строку.
- Codex: новая модель в `model/list` появляется в меню, исчезнувшая удаляется; `ultra` проходит до `turn/start`.
- Меню: «Авто (среднее)»; уровень, которого нет у новой модели, сбрасывается на «Авто».
